PicoHarness 版本说明

固件版本号写在 code.py 的 VERSION 常量里；上位机版本以仓库提交为准。
界面与固件要配套：旧固件收不到新命令，会回 "unknown cmd"。


[20261012 0.1.16-spi]

加 SPI 总线。固件新增 spi.cfg / spi.release / spi.xfer 三条命令，read_state 新增
cfg_spi 与 spi 列表，ready.caps 新增 spi 对象（groups / max_buses / max_cs / baud_ceiling）。

引脚合法性来自 tools/spi_probe.py 的上板实测，不是数据手册推导——两者在"哪些脚可路由"
上确实不一致。穷举每个有序 (SCK, partner) 组合，53 个被接受，正好落在两组里；
1571 组配对报 Invalid pins，100 个三元组是这两组的笛卡尔积。结论写进静态表 SPI_GROUPS，
开机不扫描（扫描要 1600+ 次构造调用，而答案是芯片属性，不会因接线而变）。

端口行为决定了 API 形状：构造函数只收位置参数（baudrate= 直接 TypeError，
half_duplex= NotImplementedError），只给 SCK 会被拒（Must provide MISO or MOSI pin），
因此速率与模式在建好之后于锁内 configure()。半总线（缺 MOSI 或缺 MISO）合法，
和 UART 一个口径。片选不属于 busio.SPI：固件把每路 CS 当普通输出脚，空闲为高、
事务期间拉低，于是一条总线最多带 SPI_MAX_CS=4 路器件；CS 同样登记 owner="spi"，
在界面上算占用，防止主机用 gpio.set 在事务中间改动选中状态。

时钟沿用 PWM 的 hfreq 诚实口径，字段名 hbaud：rp2 只能把 150 MHz 除以偶数整数，
上限 75 MHz，所以请求 2 MHz 实跑 1973684 Hz、10 MHz 实跑 9375000 Hz，卡片把这行打在结果里。
这个口的全双工只有 write_readinto() 一个调用且要求等长缓冲区，
固件把短的写用 0xFF 补到 max(len(w), r)，读回截前 r 字节。

界面新增 SPI 泳道（总线卡片：SCK/MOSI/MISO 三个数据槽 + CS0..CS3）与事务台，
一次一笔原始字节事务，支持"保持片选"做分两段的事务、片选下拉选"—"表示全程不动片选。
跨组的脚拖不进去，第三路总线在界面就被挡下。配置随其它总线一起进 localStorage，
漂移对账把 cs 顺序、baud、mode 都算进签名。


[20261012 0.1.15-pwmhz]

固件把 PWM 的真实频率说出来。rp2 的分频器只能生成 125 MHz/(div×(top+1))，实测下限 9 Hz：
请求 1..8 Hz 全部跑 9，高频也量化（1000→990、2000→2035）。read_state 的 pwm 条目新增
hfreq（slice 实际频率），freq 仍是你请求的值。界面上频率框随之描成琥珀色并给出 tooltip，
偏差超过 5% 时再往日志写一条。低于 1 Hz 照旧由固件拒绝（PWMOut 只吃整数）。

顺带修掉一个会致盲的坑：pwm.cfg 建对象失败时（同 slice 要第二个频率会回
RuntimeError: Conflicting settings for shared resource）引脚已 claim 成 pwm 却没有对象，
read_state 因此抛 TypeError，之后整个 gpio.state 都不可用。现在失败路径退还所有权。

界面修复：点芯片再点泳道从前只对 I2C/UART 的卡槽有效，四条 per-pin 泳道只挂了
dragover/drop，点亮着的泳道毫无反应——而选中提示的文案正是"点击高亮泳道绑定"。
现在 click 与 drop 走同一个 assign 路径，点引脚池也能解绑选中脚。附带修掉提示里
"GPGP4" 这种重复前缀（pinLabel 已含 GP，文案又写死了一个）。


[20261012 0.1.14-uart01]

probe_uart 不再把 GP0/GP1 从候选里剔除：单口形态时这对 UART0 TX/RX 被 CircuitPython
控制台占着（实测 busio.UART 报 "GP1 in use"），换成现在的双口固件后实测可用——
uart.cfg tx=0 rx=1 / tx=0 单脚 / rx=1 单脚 三次建总线全部 ok，release 之后
gpio.state 的 uart 列表为空、cfg_uart=0。GP0/GP1 因此回到 caps.uart 的 tx/rx/pairs 里。

界面侧无改动：能力表是设备报上来的，重连一次就自动高亮 GP0/GP1 的 T / R 角标。
文档同步：01 的 UART 注意事项与硬件表、02 §2.1、03 的 GP0/GP1 段落都改成"可用"。


[20261012 0.1.13-dualcdc]

固件改双 CDC 拓扑：boot.py 里 usb_cdc.enable(console=True, data=True)，
code.py 的 JSON 行协议与二进制帧走 data 口，console 口还给 CircuitPython 自己
（开机横幅、print、异常回溯、REPL）。

新增 hello 命令：应答与开机 ready 广播同一份载荷。caps 只在开机时探测一次并缓存
（I2C 穷举慢），后接入的主机不再需要重启设备即可拿到版本与能力表。

上位机用 nonce ping 认口：两个 CDC 口共用同一 VID/PID，getInfo() 区分不了，
只有应答里带回随机数的那个是 code.py。已授权端口**并行**探测，第一个正答复一到就开始连接，
角色结论缓存 4 秒，重连零点击也不再等超时。所有端口都不应答时才踢设备程序，
且候选按"探测期间谁有设备输出"来挑——data 口不吃 Ctrl+C/Ctrl+D，踢它是唤不醒 code.py 的。

控制台新增"连接日志口"按钮：双口板子在握手后自动挂上 console 口，设备 print/异常实时镜像，
没挂上时按钮还能手点。状态灯把端口角色摆在明面上：
"已连接 · 双口 · 日志口 ✓"，单口板显示"已连接 · 单口·旧模式"并在页面顶部常驻一条警告。
进入 REPL 只动 console 口，数据口的连接不会断，所以退出 REPL 无需重新选口；
但要说清楚：REPL 靠 Ctrl+C 停掉 code.py，这段时间协议**没人应答**，双口只是免掉了重选端口。

控制台新增"协议流"开关：默认关闭，打开后把协议端口的原始 JSON/二进制字节也写进终端，
用于对着线上格式查协议。

顶部新增"配置 ▾"菜单：导出配置为 picoharness-config-<时间戳>.json、导入并立刻下发、
清空前先确认。连接状态下的握手会用设备能力表核对绑定，把这块固件带不动的脚解除并在控制台点名，
所以从别的板子拷来的配置不会再"看着在跑其实一直失败"。

失败提示改成"现象 → 原因 → 下一步"三段式，例如"未找到协议端口"直接给出缺 code.py、
boot.py 没硬复位两种原因和对应的动作。

兼容回落保留一个版本：G: 上没有 boot.py 时 usb_cdc.data 为 None，固件回单口；
上位机 hello 失败即走"重启设备等 ready 广播"的老路径。下一版不再支持单口模式。

两条真机约束：boot.py 只有硬复位才生效（Ctrl-D 软重启不会重跑它）；
CircuitPython REPL 收 \r\n，只给 \n 的行会被回显但永不执行。

固件与界面分开提交（feat(fw)、feat(ui)）。


[20261011 0.1.11-uart]

UART 总线泳道落地：TX/RX 槽、波特率、写读事务台。

控制台新增 UART 实时终端标签页，每路总线一个，键盘直接发字节，
支持 HEX 与文本渲染切换。清屏/复制/导出按钮跟随当前可见标签。

UART RX 改为事件流（订阅主题 uart.<id>），空读不再阻塞调度。

修复：busio.UART 默认 1000 ms 读超时会让整个协作式事件循环冻住，
建总线时显式设 timeout=0，手动读取用 200 ms 有界等待并在读后恢复。

修复：GP0/GP1 被 CircuitPython 串口控制台占用，探测表已将其从
caps.uart 中剔除，避免界面上选了必定失败的引脚对。

修复：每次新握手清除总线卡片的 live/rejected 闩锁。此前重刷固件后
设备易失配置丢失，而旧闩锁会让界面永久跳过该总线、不再重发配置。

I2C 与 UART 泳道分别提交（feat(i2c)、feat(uart)）。


[20261010 0.1.7-i2c]

I2C 原始总线事务泳道：i2c.cfg / i2c.scan / i2c.xfer / i2c.release，
支持纯写、纯读、repeated-start 写读三种事务。

固件启动时穷举合法 SCL/SDA 有序对，暴露为 caps.i2c_pairs；
界面按角色高亮可放槽，非法拖拽直接拒绝。

rp2 PIO I2C 合法性规则确认为：SCL 取奇数 GP，SDA 取偶数 GP，
且 SDA ≡ SCL−1 (mod 4)。"No pull up found" 属接线问题，与引脚选择无关。

多脚总线接入方式：FunctionDef 增加可选 renderLane 钩子，总线泳道自渲染卡片；
配置持久化新增 buses[]。


[20261010 0.1.6-temp-sub]

新增内部温度虚拟通道（线上引脚号 100）。本 build 不暴露
board.TEMPERATURE_SENSOR，改由 microcontroller.cpu.temperature 反演
16 位等效 raw，从而完全复用既有 u16 遥测管线。

新增 MQTT 式事件订阅 sub/unsub（含保留值快照）。
主题 gpio.in 严格门控，adc.<pin> 只调每通道死区（ADC 无轮询兜底，不门控）。

示波器面板重写：通道颜色按引脚稳定分配；滚轮按光标处采样点锚定缩放；
拖拽平移；十字标线与读数框；Roll / FIFO 双采集模式与可选深度；
二进制帧引入 kind 注册表，新增遥测流只需注册解析器。


[20261010 0.1.5-binstream]

adc.stream 支持 fmt=bin，用 struct 帧传输（0xAA 'W' + u16le 长度 + payload），
单次原子写入 usb_cdc。JSON 一律用紧凑分隔符，同体积省约 15%。

上位机改为字节级混流解析，能同一串口流里分开 ASCII 行与二进制帧。

ADC 芯片读数加 EMA 平滑与 250 ms 定时刷新；示波器加轴单位与 k·x+b 校正。


[20261010 0.1.4-adcstream]

新增 adc.stream / adc_streamer 批量波形帧，流开启期间死区事件静音。
示波器面板（可折叠，4 通道，2048 点环形缓冲，rAF 重绘，选择与折叠状态持久化）。

修复：三通道并发下的界面卡顿。实测固件与协议层不慢
（0 通道 RTT 中位 11 ms，3 通道 19 ms，零超时），
根因是逐事件渲染，已由批量帧 + 单帧重绘消除。


[20261010 0.1.3-stdinpoll]

修复：sys.stdin.read(1) 会阻塞直到有字节到达，此前 command_reader 第一步就冻住
整个事件循环，所有兄弟 monitor 永远得不到步进。现用 select.poll() 门控 stdin，
并按官方指南用任务句柄 gather。

修复：mpy 下 gather 对裸协程的顺序 await 问题；gather 只收 Task 对象。

PWM 频率编辑器重做为"数值预设 × 单位预设"组合，浮点安全持久化。

已知设备侧限制：rp2 固定频 PWMOut 改 .frequency 会抛 Invalid variable_frequency，
固件改为频率变化时重建对象；频率只收整数 Hz，下限约 7.4 Hz。
USB CDC 上 print(flush=True) 每次抛 OSError [Errno 22]（文本已出），故不 flush。


[20261010 0.1.0-adc / 0.1.1-montdbg]

新增 ADC 读取泳道：adc.cfg / adc.stop，100 ms 采样、约 0.5% 死区变化推送。
显示以电压为主，可切原始值；格式选择随配置持久化。

新增 dbg 事件上报各 monitor 任务的存活与异常（此前 gather 会吞掉已死任务，
故障时表现为静默）。引脚模型扩到 29 脚，ADC 显示在 V/mV/raw 间循环。


[20261009 0.0.9-nbstdin]

命令读取改非阻塞，修复"回答应等到下一次请求才出现"。

界面新增控制台复制/导出；PWM 频率预设下拉；工作台配置存入浏览器 localStorage，
连接后静默恢复并靠漂移对账自愈。


[20261009 0.0.8-async]

固件改 asyncio 主循环，gpio_in 边沿事件 50 ms 推送
（CircuitPython 不内置 asyncio，需 circup install asyncio）。

上位机输入电平改为事件驱动，轮询降为 1 s 对账自愈。


[20261009 0.0.7-arbiter]

固件加命令分发表与引脚所有权裁决（claim/release，PWM 抢占可 force）。

上位机分层重构：transport / rpc / model / workbench，
功能以 FunctionDef 注册，新增总线功能只需写 def 并注册。


[20261009 0.0.6-wb]

IO 分配工作台（引脚池 + 功能泳道，拖拽或点选绑定，占用自动顶位）。
调试控制台集成 xterm.js，中英双语。

更早的历史不在本篇范围：项目以 PicoJig 为蓝本，改为 CircuitPython +
