PicoHarness 构建说明

本篇讲怎么从源码做出交付物、怎么部署到板子、以及改完代码怎么验证。
使用方式见 "01_GUIApp_FW_Manual"，接口定义见 "02_Library_User_Guide"。


[前提条件]

以下版本已验证可用：

Node.js：24.18.0
npm：随 Node 附带
浏览器：桌面版 Chrome 或 Edge（需要 Web Serial API）
开发板：Raspberry Pi Pico 2（rp2350a）
设备固件：CircuitPython 10.3.1（board_id：raspberry_pi_pico2）

仓库依赖只有 esbuild、typescript 和两个前端运行时（xterm.js）。安装：

    npm install

设备侧需要一个 asyncio 实现（CircuitPython 不内置）。用 circup 装到板子的 lib 目录：

    circup install asyncio

装完 CIRCUITPY 卷下应存在 lib/asyncio/ 与 lib/adafruit_ticks.mpy。
以后动设备库一律走 circup，不要手工拷贝。


[交付物构建]

    npm run build

产物是单文件 dist/index.html（JS/CSS 全部内联，约 400 KB），双击即可在 file:// 下使用，
不需要起服务器。dist/ 已被 git 忽略，不要提交。


[固件部署]

固件是两个文件：src/fw/boot.py（开双 CDC）和 src/fw/code.py（协议本体），都要拷到
CIRCUITPY 卷根目录（下文记作 G:）：

    cp src/fw/boot.py /g/boot.py
    cp src/fw/code.py /g/code.py

注意：

写入后板子立即软复位，正在连接的 Web Serial 会掉线，需要在界面重新点 Connect。
boot.py 只在硬复位时生效（按 RESET 或重新上电；Ctrl-D 软重启不会重跑它）。
刚拷完 boot.py 请硬复位一次，否则设备仍只有一个 CDC 口，caps.usb.data 会是 false。
G: 根目录若存在 main.py，CircuitPython 就不会再运行 code.py（main.py 优先级更高）。
boot.py 里只写 usb_cdc.enable(...)，不要占 GP0/GP1、更不要提前建总线对象——
引脚裁决者在 code.py 里，boot.py 抢了串口控制台就没法用了。
G: 上没有 lib/ 时说明 circup 没装成功，code.py 会以 ImportError 起不来。

双 CDC 之后设备在系统里是两个 COM 口：console 口给 CircuitPython 的横幅/print/回溯/REPL，
data 口跑本项目的 JSON 行协议与二进制帧。两个口共用同一 VID/PID（0x2E8A:0x000B），
设备管理器与 navigator.serial.getInfo() 都区分不了，只有 nonce ping 能认出口色，
界面已经按这个规则自动识别，人工排查时也别靠端口号猜。


[类型检查]

仓库里没有 tsconfig.json。直接跑 npx tsc 会报 TS5058，必须显式给参数：

    npx -p typescript tsc --noEmit --strict \
        --module esnext --target es2020 --moduleResolution bundler \
        --lib es2020,dom --skipLibCheck src/ui/main.ts

npm run build 走的是 esbuild，它只做打包，不做类型检查。改过 .ts 一定要单独跑上面这条。


[验证链]

改固件（code.py）后按顺序做：

1. 语法检查
       .venv/Scripts/python.exe -m py_compile src/fw/code.py
2. 部署到板子（见上）
3. 用 pyserial 直接问设备，确认新命令和字段真的在。双 CDC 之后有两条路：
   - 省事的路：不带参数跑 tools/serial_probe.py。它按 VID/PID 找出两个口，用 nonce ping
     分辨口色，从 console 口重启 code.py，在已挂住的 data 口读开机 ready 广播，
     再依次跑 hello / ping / echo。
   - 自己写脚本：能答 {"cmd":"ping"} 并带回 nonce 的是 data 口（协议），
     另一个是 console 口，只吃控制字节和 REPL 语句。
     先打开 data 口并保持读端、再动手重启：CircuitPython 在没有人持有该端口时
     会直接丢掉 CDC 输出，开机 ready 广播只有已经挂上读端时才收得到。
     重启 code.py：往 console 口发 \x03 停掉当前程序 → 等 0.5 s → 发 \x04；
     第二个 \x04 兜住"第一个只把 REPL 叫醒"的情况。
     REPL 语句必须以 \r\n 结尾，只给 \n 的行会被回显但永不执行。
   脚本要用 venv 里的 python（pyserial 只装在 .venv，系统 pip 不通网）。
   输出走 sys.stdout.buffer.write，GBK 控制台打印 UTF-8 会炸。
   设备启动会先发一段设置终端标题的 ANSI/OSC 转义，粘在 ready JSON 前面且不带换行，
   脚本要用正则剥离或按花括号定位提取。

改界面前按顺序做：

1. 类型检查（见上）
2. npm run build
3. 浏览器打开 dist/index.html 做 DOM 冒烟：断言元素存在、交互生效、控制台无报错。
   没板子也能测大部分逻辑——泳道绑定、拖拽高亮、持久化都不依赖设备。
   认口/日志口/REPL 这类端口逻辑可以用假 navigator.serial（两个内存 FakePort，
   一个答 ping 一个只答 REPL）在无设备环境下跑完整条链路。
   测试结束记得清 localStorage（key：picoharness-config-v1、picoharness-scope-v1）。

[排障判据]

界面发了新命令、设备回 "unknown cmd"，或者 gpio.state 应答里缺新字段、
ready.caps 里没有 uart/i2c_pairs —— 这不是前端 bug，是 G:\code.py 还是旧版本。
先比对设备端 code.py 里的 VERSION 字符串与源码，重新拷一次即可。
只看到一个 COM 口、或 ready.caps.usb.data 为 false —— 是 G:\boot.py 没拷进去，
或者拷完没做硬复位（Ctrl-D 不算）。

[固件实现要点]

主循环是 asyncio 任务组：command_reader 读 stdin、gpio_monitor 边沿推送、adc_monitor 死区推送、
adc_streamer 波形批量流。每个协程先 create_task 拿到 Task 句柄，再 await gather(t1, t2, ...)。
该 mpy 端口的 gather 只接受 Task 对象，塞裸协程会在 sleep_ms 处触发 "missing await" 断言。

四条真机实测出来的约束，动调度之前务必知道：

1. sys.stdin.read(1) 会阻塞直到至少一个字节到达，它不是"无数据返回 None"的非阻塞惯用法。
   不加门控时 command_reader 第一步就冻结整个事件循环，所有兄弟 monitor 永远得不到步进
   （这正是当初 ADC 读不到数的根因）。双 CDC 后 data 口同理：先读 in_waiting 再 read，
   并把 DATA.timeout 设为 0；单口回落路径仍用 select.poll() 门控 sys.stdin。
2. busio.UART 默认 timeout=1000 ms，一次空读就能把协作式循环整段卡住；建总线时显式 timeout=0。
3. USB CDC 上 print(..., flush=True) 每次写完抛 OSError [Errno 22]（文本已正常输出），不要显式 flush。
4. usb_cdc.Serial 是二进制流：read() 给 bytes、write() 收 bytes-like，
   而 sys.stdin 是文本对象。两者混在一条读取路径里时必须先 decode("utf-8","replace")，
   否则同一处缓冲会同时炸出 TypeError 和半个中文行。

另外：rp2 固定频率模式的 PWMOut 写 .frequency 会抛 Invalid variable_frequency，
固件改成频率变化时 deinit 重建。mpy 的 asyncio 端口本身是队列轮转调度器，
create_task 并发没有缺陷（早前"gather 按顺序 await 饿死子任务"的诊断已被真机证伪）。

界面侧的分层与依赖方向见仓库 README 的"架构"一节，这里不重复。
一条硬约束：层间依赖单向向下，workbench/ 下每个功能是一个 FunctionDef 插件，
新增总线功能 = 写 def(+driver) 并注册进 defs 数组，同时在固件 COMMANDS 表里注册命令。

[提交约定]

git commit 标题一律用 type(scope): subject，例如 feat(uart): ...、fix(fw): ...。
固件版本号写在 code.py 的 VERSION 常量里，随功能变更一起提升。
