# PicoHarness 使用示例

这篇不讲接口，只讲"我想做某件事，该怎么点"。
每个 recipe 都是独立可做的，按需要挑着看。
看不懂某个报错就翻到最后的 [故障排查表](#11-故障排查表)。

前提：板子已经按 [01 使用手册 §2](../01_GUIApp_FW_Manual/README.md#2-准备板子) 准备好，
上位机连上、状态灯显示 ready、握手日志里能看到 `caps`。

约定：下文 GP0..GP28 都指 Pico 2 引出脚，GND 指板上任意地。
所有引脚绑定都可以拖，也可以"点芯片 → 点泳道槽"，两种写法混用不额外说明。

---

## 1. 把引脚当开关用：GPIO 自环

**目的**：确认整条链路（浏览器 → 串口 → 固件 → 引脚 → 回到浏览器）是通的。
一根杜邦线就能做完，不需要任何外部器件。

**接线**：

```
GP2 ──杜邦── GP3
```

**步骤**：

1. 把 GP2 拖进"数字输出"泳道，GP3 拖进"数字输入"泳道。
2. 点界面里的输出芯片，让 GP2 输出高。
3. 看输入泳道上 GP3 的 LED：应该跟着亮。
4. 再点一次，两边一起变低。

**为什么这就算验证通过了**：输出侧走的是"请求/应答"，输入侧走的是"事件推送"，
两条不同的路径同时工作，才说明链路完整。如果输入 LED 不动，先看输出芯片是否真的变高了。

**注意**：GP3 是输入，别同时把它拖进输出泳道——同一个脚同一时刻只能属于一个功能，
后绑定的会把先绑定的顶掉，界面上会如实显示。

## 2. 读一个模拟量：电位器 / 光敏

**目的**：看电压随时间变化，顺便验证波形面板。

**接线**（三引脚电位器，中间是滑动端）：

```
电位器左脚 ── 3V3(OUT)
电位器中间 ── GP26
电位器右脚 ── GND
```

**步骤**：

1. 把 GP26 拖进"ADC 读取"泳道。
2. 芯片上默认显示电压（V），点 `V/raw` 按钮可以切回 16 位原始值。
3. 转动旋钮，数值应该跟着平滑变化。
4. 打开下方示波器面板，点 `26` 通道按钮，曲线开始滚动。
5. 想看得更细：把采样间隔调到 25 ms，模式切到 FIFO，深度选 1024 或 2048。
6. 需要标定就在该通道的 `k·x+b` 里填系数，比如探针是 1/3 分压就填 `k=3, b=0`。

**能读 ADC 的脚**：只有 GP26、GP27、GP28（外加内部温度虚拟通道）。
握手日志的 `caps.adc` 就是权威名单，别的脚拖不进 ADC 泳道。

## 3. 看一眼板子温度：内部温度通道

**目的**：不接任何东西，验证遥测流和温度校正曲线。

**步骤**：

1. 引脚池里会多出一颗 `TEMP` 芯片（它是虚拟通道，不占物理引脚）。
2. 把 `TEMP` 拖进"ADC 读取"泳道。
3. 芯片默认显示 °C。切到 raw 看到的是反演出来的 16 位等效值，不是原始寄存器。
4. 用手按住 Pico 2 的芯片十几秒，数值应缓慢上升；松开后回落。

**能信的精度**：±1~2 °C。rp2350 的温度曲线本身有个体差异，别拿它当温度计标定用。
温度通道走的是和其它 ADC 通道完全一样的管线（同死区、同波形流、同环形缓冲），
差别只在显示单位上。

## 4. 出 PWM：LED 调光 / 定频方波

**目的**：驱动 LED 做亮度调节，或给下游电路提供时钟。

**接线**：

```
GP7 ── 330Ω ── LED 正极，LED 负极 ── GND
```

**步骤**：

1. 把 GP7 拖进"PWM"泳道。
2. 频率输入框旁边点 ▾，从数值预设（1/2/5/10/…/1000）里选一个，再选单位（mHz/Hz/kHz/MHz）。
3. 拖占空比滑条，LED 亮度跟着变。

**两个一定会踩的坑**：

- **同一 slice 的两个脚，频率是绑在一起的**。rp2 的 PWM 一个 slice 只有一台计数器，
  两个脚共用一个频率。想两个脚跑不同频率，就按 `(n // 2) mod 8`（n ≥ 32 用
  `8 + ((n - 32) mod 8) // 2`）算出各自属于哪个 slice，选算出来不同的（例如 GP7 是 slice 3、
  GP11 是 slice 5）——**"不相邻"不等于"不同 slice"**，GP16/GP17 就又绕回 slice 0。
  或者干脆接受同频只改占空比，**或把其中一路切到 PIO**（它数自己的 tick，不看 slice 分组）。
  给第二个脚要求别的频率时，`pwm.cfg` 不会覆盖
  第一个脚，而是直接失败回 `Conflicting settings for shared resource`，那个脚回到引脚池。
- **硬件 slice 低频有下限**。rp2 固定频率模式只吃整数 Hz，实测最低 9 Hz：填 1～8 Hz 板子都跑 9 Hz，
  高频也会量化（1 kHz 实际 990 Hz）。固件把真实频率回报给界面，频率框会变琥珀色并写明
  "硬件实际 Y Hz"；填 0.5 Hz 这类低于 1 的值，`hw` 这路直接报错。
  **要真低频就点频率框左边的 PIO**：那一路由状态机自己数 tick，实测 0.1 Hz 稳稳输出
  （回报 0.099986 Hz），窗口一直低到 0.0174553 Hz。代价是每路吃掉一个状态机，全芯片只有 12 个。

**想抓波形**：把 PWM 脚用杜邦线引到隔壁的 GP26，ADC + 示波器就能看到自己的方波。
不过 ADC 流最快也就 10 ms 一批，看高频方波会严重走样，只适合看慢速占空比变化。

## 5. 扫 I2C 总线

**目的**：确认接线、找到器件地址。

**接线**（以 GP8=SDA、GP9=SCL 为例）：

```
GP8 ── SDA ─┬─ 器件 SDA
GP9 ── SCL ─┴─ 器件 SCL
3V3(OUT) ── 器件 VCC
GND     ── 器件 GND
```

**步骤**：

1. I2C 泳道点"＋ 添加总线"，出现一张卡片。
2. 把 SCL 拖进卡片里标着 `SCL` 的槽、SDA 拖进 `SDA` 的槽。
   **只有合法的脚会亮起来**——不合法的槽拖不进去。
3. 选时钟（默认 100 kHz），卡片变"已建立"。
4. 在地址框留空或点扫描，得到在线地址列表。

**为什么很多脚用不了**：rp2 的 I2C 走**硬件 DW_apb_i2c 外设**（不是 PIO，也没有位模拟兜底），
合法与否是**一对引脚**的属性，不是单个引脚的属性。规则是：SCL 取奇数 GP，SDA 取偶数 GP，
且 `SDA ≡ SCL−1 (mod 4)`（两脚不必相邻，GP13+GP4 也算一对）。
所以 GP8/GP10 这样两个偶数脚永远配不成一条总线。
握手日志的 `caps.i2c_pairs` 里是按这条规则枚举、再由固件真建一次确认的完整合法表，
界面高亮就是照它来的。

**`No pull up found on SDA or SCL` 不是引脚选错了**。这条报错的意思是"引脚对合法，
但两条线没有被拉到高电平"——典型原因是没接器件、没接上拉、或者 VCC/GND 忘了接。
查接线，别查代码。

## 6. I2C 原始事务：读一个寄存器再写回去

**目的**：不依赖器件驱动，直接做总线事务。

**步骤**（接上一个 recipe 的总线，假设器件地址 0x68）：

1. 事务台选"读"，地址填 `0x68`，读长度填 `1`，发送 → 拿到首字节。
2. 想读某个寄存器：选"写读"(wr)，写数据填寄存器号，读长度填期望字节数。
   这会走 repeated-start，中间不会释放总线。
3. 想配置器件：选"写"，写数据填 `[寄存器, 值]` 两个字节。
4. 数据框收十六进制文本，`0x68`、`68`、`de ad be ef` 都能识别，空格随意。

地址是 7 位制，范围 0..127。如果界面显示的是 8 位地址（很多资料把 R/W 位也算进去，
比如 0xD0），右移一位再填。

## 7. UART 自环：一块板跟自己说话

**目的**：验证 UART 通路，看到自己发出去的字节回来。

**接线**：

```
GP6 ──杜邦── GP7
```

GP6 是 TX、GP7 是 RX（偶数脚做 TX、奇数脚做 RX，且要在同一个硬件 UART 实例上）。

**步骤**：

1. UART 泳道点"＋ 添加串口"。
2. TX 槽放 GP6，RX 槽放 GP7（只放一个也行，见下方说明）。
3. 波特率保持 115200。
4. 控制台切到 `UART #0` 标签页，直接敲字回车——自己发的字符应该出现在同一个终端里。
5. 想看原始字节：用卡片上的 Send/Read 发 `aa 55 aa`，回来应是 `AA 55 AA`。
6. 点标签栏的 `HEX` 按钮，收到的字节按大写十六进制显示；再点切回文本。

**允许半总线**：只绑 TX 或只绑 RX 都合法（与 I2C 必须两线不同）。
只绑 TX 就只能发不能收，只绑 RX 就只能收不能发，写的时候界面上会照实拒绝。

**GP0/GP1 现在是合法候选**：它们在 Pico 2 上就是 rp2350 UART0 的 TX/RX。单口那会儿它们被
CircuitPython 自己的串口控制台占着，一用就报 `GP1 in use`，所以旧固件的探测表把这对脚剔除了；
现在这版双口固件上实测 `uart.cfg tx=0 rx=1` 建总线成功，它们已回到 `caps.uart`，
引脚池里也会正常高亮成 UART 候选。

## 8. UART 两板对话

**目的**：用两台 PicoHarness 当两台串口终端互发消息。

**接线**：

```
A板 GP6(TX) ──► B板 GP7(RX)
A板 GP7(RX) ◄── B板 GP6(TX)
A板 GND     ──── B板 GND     ← 这根必须接
```

**步骤**：

1. 两块板各拷一份 `boot.py` + `code.py`，各硬复位一次，各插一台 USB。
2. 开两个浏览器标签，各连一块板：选择框里这块板的条目全选，
   页面自己会认出哪个是数据口（双口板每块列两条）。
3. 两边都建 UART 总线（都用 GP6/GP7 没问题，它们是各自的硬件）。
4. 两边都切到 `UART #` 标签，一边打字，另一边看。

**GND 不接会怎样**：电平没有共同参考，收到的字节随机翻转。
这是两板对话最常见的失败原因，症状是"能收到东西但是乱码"。

**波特率两边要一致**。115200 下 8N1，不一致通常表现为固定比例的乱码而非全错。

## 9. SPI 事务：读一枚 Flash 的 JEDEC ID

**目的**：搞清楚这个事务台到底往总线上发了什么——它一次只做一笔全双工，
写和读是**同一串时钟**同时发生的，不是"写完再读"。

**接线**（以一颗 SPI Flash 为例）：

```
板子 GP2 ──── SCK
板子 GP3 ──── MOSI（器件的 DI）
板子 GP4 ──── MISO（器件的 DO）
板子 GP5 ──── CS#
板子 GND ──── GND
```

GP2/GP3/GP4 是**同一组**里的 SCK/MOSI/MISO，所以这么摆合法。
换成 GP2/GP3/GP8 就跨组了，界面不会让你绑上。
GP5 不在 SPI 数据脚表里——片选是普通输出脚，任何空闲 GP 都能当。

**步骤**：

1. 把 GP2 拖进 SCK 槽、GP3 进 MOSI、GP4 进 MISO，再把 GP5 拖进 **CS0** 槽。
   卡片上 CS0..CS3 四个槽是一直摆着的，填了哪几个，片选下拉里就出现哪几个。
2. 时钟选 1 MHz，模式选 0（CPOL=0 / CPHA=0，大多数器件的默认）。
3. 写(hex) 填 `9f`，读字节 填 `4`，片选选 `CS0`，勾掉"保持片选"，点**传输**。
4. 结果行形如：

```
FF EF 40 18  ·  读回 4 字节  ·  实际 1000000 Hz
```

**为什么读 4 个字节**：0x9F 这个命令自己占 8 个时钟，
后面才是 3 个字节的 ID。全双工意味着发命令的这 8 个时钟同样在收，
所以第一个收到的字节是器件还没开始输出时的电平，真正的 ID 在第 2..4 个字节。
固件把你短的 `w` 用 `0xFF` 补到和 `r` 一样长，因此总线上实际跑的 4 字节是
`9F FF FF FF`——这正好是 RDID 想要的：命令之后 MOSI 上给什么都不重要。

**想分两段发**（有些器件要求在命令和读之间做别的事）：

| 次序 | 写(hex) | 读字节 | 保持片选 | 总线上的动作 |
| --- | --- | --- | --- | --- |
| 1 | `9f` | `0` | 勾上 | CS 拉低，发 8 个时钟，CS **不抬** |
| 2 | 空 | `3` | 不勾 | 接着发 24 个时钟读回 3 字节，然后 CS 拉高 |

第 2 笔的片选仍然是 `CS0`：那根线本来就是低的，再拉一次不产生新的边沿，
所以这是一次连续选中，不是两笔独立事务。做完记得最后一笔把"保持片选"放开，
否则 CS 会一直停在低位，器件那边还等着你继续。

**读到的 ID 全对不上**：先确认片选是不是被漏了——片选下拉里如果选的是"—"，
所有 CS 全程保持高，器件根本没被选中，总线上只有时钟在跑，读回的是浮空值。
这个"不拉片选"的模式是故意留的，用来抓纯时钟。

## 10. 用 REPL 做临时实验

**目的**：绕过协议，直接在板子上跑任意 CircuitPython 代码。

**步骤**：

1. 控制台栏把模式切到 REPL。页面会在**控制台口**上发 Ctrl+C（还没接日志口时它自己先接上），
   并从控制台输出里确认 `>>>` 提示符。数据口全程保持连接。
2. 设备会先软复位进入 friendly REPL，你敲的内容原样进 stdin，输出原样上屏。
3. 切回 Monitor 时发 Ctrl+D，`code.py` 重新运行，重新握手，功能状态按 localStorage 恢复。

**注意**：REPL 期间所有泳道都断了——`code.py` 没在跑，也就没人应答。
示波器波形会停住，UART 终端不再收数据，这不是坏了。
另外 UART 标签页在进 REPL 时会主动让位给主终端，退订串流；回到 Monitor 再切回来即可。

## 11. 故障排查表

### 11.1 报错对照

| 现象（界面上的原文） | 原因 | 下一步 |
| --- | --- | --- |
| `unknown cmd: uart.cfg`（或任何新命令） | 板子上跑的是旧固件，浏览器侧是新界面 | 对比 `G:\code.py` 里的 `VERSION` 和源码，重新拷一次 `code.py`（会重启板子，要重连） |
| `RuntimeError: no such bus (configure it first)` | 这条总线在设备上并不存在：被拒绝过、引脚非法、或板子刚重启丢了易失配置 | 看握手日志确认 `uart`/`i2c` 列表；重连一次（新握手会清掉"已拒绝"闩锁，自动重发 `cfg`） |
| `ValueError: Invalid pins`（I2C） | 引脚对不合法：SCL 不是奇数，或 SDA 不满足 `SDA ≡ SCL−1 (mod 4)` | 换一对，或直接看 `caps.i2c_pairs` |
| `RuntimeError: No pull up found on SDA or SCL` | 引脚对是合法的，只是线没被拉高 | 查接线、上拉、VCC/GND，别改代码 |
| `ValueError: ... GP1 in use`（或 GP0） | **只有旧单口固件这样**：那时这对脚被 CircuitPython 控制台占着。0.1.14 起协议跑在独立 data 口，实测 `uart.cfg tx=0 rx=1` 建得起来 | 还在单口形态上就先补 `boot.py` 并硬复位；否则换 GP6/GP7（UART1）这类配对 |
| `RuntimeError: pin GP7 busy` | 这个脚已经属于别的功能 | 先把旧泳道上的芯片解绑，再绑新的 |
| `ValueError: freq < 1 Hz: PWMOut takes whole hertz` | `hw` 那路只收整数 Hz | 频率填 ≥1 的整数，或把这路切到 PIO |
| `ValueError: clock ... below PIO floor ...` / `freq above PIO ceiling ...` | PIO 这路要的 SM 时钟越过了实测窗口（2288 Hz – 150 MHz），也就是频率出了 0.0174553–15,000,000 Hz 之外 | 把频率挪回窗口内；界面的夹取本来就朝内，手填才可能越界 |
| `RuntimeError: no free PIO state machine (12/12 in use)` | RP2350 一共 12 个状态机，PIO 通道一人一个，已经用满 | 先解绑一路 PIO（拖回池中或点 ×），再开新的；`pio_sm_free` 会告诉你还剩几个 |
| `RuntimeError: PIO PWM unavailable: copy lib/adafruit_pioasm.mpy` | `rp2pio` 是内置的，但拼装 PIO 指令的 `adafruit_pioasm` 没进 `lib/` | 补上 `lib/adafruit_pioasm.mpy` 并硬复位；不装也行，硬件 slice 照常可用，只是界面不再出现 HW/PIO 选择 |
| `Invalid variable_frequency` | 同 slice 两脚要不同频率，或固定频率模式改 `.frequency` | 接受同频，或把两脚分到不同 slice |
| 板子串口只有 `ImportError: no module named 'asyncio'` | 没装 asyncio 到设备 | `circup install asyncio`，装完 `G:\lib` 下应有 `asyncio/` 与 `adafruit_ticks.mpy` |
| `RuntimeError: this bus has no TX pin / no RX pin` | 半总线，正常限制 | 需要收发就补上另一根线 |
| `ValueError: busio.SPI on rp2 needs at least a MOSI or a MISO pin` | 只绑了 SCK | 至少再绑一个数据脚，只发或只收都算合法 |
| `... is not a routable set: rp2 SPI pins come in fixed groups ...`（界面侧对应 `SCK/MOSI/MISO 必须来自同一引脚组（同一硬件 SPI）`） | 三个数据脚跨了两组 | 照 `caps.spi.groups` 换脚，界面上跨组的脚根本拖不进去 |
| `could not build SPI on ...: SPI peripheral in use` | 两组脚都在用了，第三条总线没有硬件可绑 | 释放一条，或把两条总线的脚并到同一组 |
| `RuntimeError: GP5 already belongs to SPI bus 0 — release it first` | 同一个脚被两条总线要（常见于片选复用） | 换一根空闲 GP 当 CS，或先释放旧总线 |
| `SPI 命令失败: no CS 1 on this bus (it has 1)` | 事务里点名的片选下标不存在 | 先在卡片上把 CS 补齐，或把下拉改回 CS0/"—" |
| `RuntimeError: this bus has no MISO pin — nothing to read` | 半总线只配了 MOSI，却要做读 | 补 MISO，或这条总线只做写 |

### 11.2 连不上、握手不动

按顺序排查，每一步都可能直接解决：

1. **另一个标签页还占着端口**。Web Serial 一个 COM 口只允许一个使用者，
   关掉其它浏览器标签再试。
2. **端口选择框里根本没有设备**。按 BOOTSEL 重新插上确认能进 UF2，
   或看设备管理器里 COM 号是否变化——换了 USB 口就会换号，双 CDC 板会列两个号。
3. **提示"未找到协议端口"，但板子是活的**。要么只授权了两个口中的一个，
   要么 `boot.py` 没生效（没硬复位）。两个口同名，页面只能靠 ping 区分，
   所以选择框里这块板的条目要全选。
4. **板子停在 friendly REPL**。`code.py` 有语法错误时不会运行，
   报错只会出现在**控制台口**（数据口一片安静）。此时用 REPL 模式或按 Ctrl+D 看具体报错。
5. **串口被别的程序占了**。串口监视器、`mpremote`、编辑器插件都会独占 COM 口。
6. **握手超时但板子活着**。设备启动时会发一段设置终端标题的 ANSI/OSC 转义，
   粘在 `ready` JSON 前面；上位机按 `{` 定位切掉了它。
   如果你自写主机脚本，记得也要处理，否则会以为是 JSON 解析失败。

### 11.3 界面表现异常

- **某个功能每秒重发一次配置**：设备一直不接受这个状态，漂移对账就每秒重下发。
  新版已经用"已拒绝"闩锁抑制住了；若仍在刷屏，把那个总线卡片删掉重建。
- **升级固件后旧功能不生效**：握手会清掉总线的 live/rejected 闩锁并重新下发配置。
  如果没生效，点一次 Connect/Disconnect 重连，等效于用户手动重试。
- **刷新页面后引脚绑定没了**：配置存在**浏览器**的 localStorage
  （`picoharness-config-v1`），不在板子上。换浏览器、换机器、开无痕窗都会看不到。
- **示波器没曲线**：确认通道按钮是亮的；ADC 通道要在泳道里已绑定；
  Roll 模式是定深滚动，数据量少时看着像"不动"，切 FIFO 更直观。

### 11.4 数据看起来不对

- **ADC 读数抖动大**：共地没接好、信号源阻抗太高（ADC 建议 <10 kΩ 源阻抗）。
  软件侧只能靠死区滤波，治不了根。
- **温度值和 `cpu.temperature` 差得多**：温度通道是数据手册曲线反演出的等效 raw16，
  0.03 °C/LSB，本来就不追求精度。
- **I2C 读回全 0x00 或全 0xFF**：地址填错了 8 位/7 位，或者器件没上电。
- **UART 收到固定比例的乱码**：两边波特率不一致。
- **SPI 读回全 0xFF 或全 0x00**：多半是片选没拉——下拉选了"—"，所有 CS 全程为高，
  器件根本没被选中，MISO 上只剩上下拉。其次才是 MISO/MOSI 接反。
- **SPI 读回的数据每次偏移几位**：CPOL/CPHA 模式和器件要求的不一致，先按器件手册改模式。
