# PicoHarness 使用手册

这份手册带你从零跑起 PicoHarness，并逐个功能讲清楚怎么用。
只关心"怎么把线接上、把界面点开"的话，读完这一篇就够了。
协议细节请看 [02 协议参考](../02_Library_User_Guide/README.md)，具体玩法和报错对照请看 [03 使用示例](../03_Sample_Program_User_Guide/README.md)。

---

## 1. PicoHarness 是什么

一块 Pico 开发板 + 一个网页，就是一台桌面测试治具。

- PC 侧交付物是**单个 HTML 文件**，双击就能用，不用装 Python、不用装驱动、不用起服务。
- 网页通过浏览器的 **Web Serial API** 直连 Pico 的 USB 串口。
  板子上有两个 CDC 口：数据口跑网页与板子之间的 JSON 协议，控制台口归 CircuitPython，
  管 `print`、异常回溯和 REPL。页面会自动认出口色，不用你猜 COM 号。
- 板子上跑一个 CircuitPython `code.py`，收 JSON 命令、控制引脚、把读数推回来。

能做什么：给引脚通断、量电压、出 PWM、扫 I2C 总线、发串口，顺便带一个示波器面板和一个能敲命令的调试控制台。

已验证环境：Raspberry Pi Pico 2（rp2350a）、CircuitPython 10.3.1、桌面版 Chrome / Edge。

## 2. 准备板子

### 2.1 烧 CircuitPython

去 <https://circuitpython.org/board/raspberry_pi_pico2/> 下载 UF2（用别的板子就换对应页面）。

1. 板子断电：拔掉 USB 线。
2. 按住板上的 BOOTSEL 按钮，把 USB 线插回电脑，松开按钮。
3. 电脑上会出现一个名为 `RPI-RP2` 的 U 盘。
4. 把 `.uf2` 文件拖进这个 U 盘。板子会自动重启。
5. 重启后出现名为 `CIRCUITPY` 的 U 盘，说明烧写成功。

### 2.2 装固件依赖

`code.py` 的事件循环需要 `asyncio` 库，而 CircuitPython 不内置它。缺了会在串口终端报
`ImportError: no module named 'asyncio'`。

最省事的做法是用 circup（在电脑上装一次即可）：

```bash
pip install circup
circup install asyncio
```

circup 会自动把 `asyncio` 和它依赖的 `adafruit_ticks` 装进 CIRCUITPY 卷的 `lib/` 目录，
版本也会匹配你的 CircuitPython。

不想装 circup 的话，手动下载 [Library Bundle](https://circuitpython.org/libraries)，
把里面的 `asyncio` 目录和 `adafruit_ticks.mpy` 复制到 `CIRCUITPY/lib/`。

### 2.3 放固件

固件是两个文件，都复制到 CIRCUITPY 卷的根目录，覆盖同名文件：

- `src/fw/boot.py`：只做一件事——`usb_cdc.enable(console=True, data=True)`，
  把 USB 串口拆成"控制台口"和"数据口"两个。
- `src/fw/code.py`：治具本体，收 JSON 命令、控制引脚、把读数推回来。

`boot.py` **只在硬复位后生效**：按板上的 RESET 键，或拔插一次 USB。
Ctrl-D 软重启不会重跑它，所以拷完记得硬复位一次——设备管理器里出现两个 COM 口才算成功。

如果根目录里有 `main.py`，把它删掉或改名：CircuitPython 只运行 `main.py`，
有了它就不会碰 `code.py`。

复制完成，板子会自动重启并开始运行。这一步不需要在电脑上装任何东西。

> 以后每次换了 `code.py`，都是同一个动作：复制过去，板子自动重启。
> 重启会断开浏览器那边的串口连接，重连一下就行。换 `boot.py` 要多一步硬复位。

## 3. 打开上位机

拿到 `dist/index.html`（自己构建的方法见 [04 构建指南](../04_FW_Build_Guide.txt)），
双击用 Chrome 或 Edge 打开。`file://` 直开就能用，不需要起本地服务器。

点页面顶部的**连接设备**。两个 CDC 口共用同一厂商/产品 ID，浏览器给不出名字，
所以页面靠"问"来认口：给每个已授权的端口**同时**发一条 ping，只有回了随机数的那个是数据口；
结论会缓存 4 秒，所以断开再重连基本是瞬间的事。

- 第一次用：浏览器弹串口选择框，把列出的板子条目**全部选中**（一般显示为
  `USB Serial Device` 或带 `2E8A` 厂商 ID 的项，双口会有两条），授权之后就不再弹框。
- 以后重开页面：直接零点击重连，端口已经授权过了。
- 板子上的程序没在跑（停在 REPL 或崩了）：页面会在**有设备输出的那个口**上补一发
  `Ctrl+C` + `Ctrl+D` 把它踢起来，然后再认一次口。数据口不吃控制字节，
  所以踢错了口是唤不醒板子的——这也是页面按"谁的动静大"来挑候选的原因。
  此时不会再弹第二次选择框：已授权的端口都不应答，只是 `code.py` 没在跑而已。

握手拿到的是设备自己报上来的能力表，不重启板子（`hello` 命令）。

连接成功后：

- 顶部状态灯变绿，文字形如 `已连接 · 双口 · 日志口 ✓`。第二段告诉你板子是真双口
  还是 `单口·旧模式`；第三段是日志口的状态，`日志口未连接` 时手点一下**连接日志口**即可。
  双口板子在握手后会自动去挂日志口，成功就不需要你动手。
- 下方控制台打出握手信息。
- 工作台的引脚芯片上会出现能力角标（P=PWM、A=ADC、S/D=I2C、T/R=UART）。

那些角标是**板子自己报上来的**，不是写死在页面里的。所以换一块板子、
或者某个脚被占用，界面上会如实反映，不会出现"看着能用其实不能用"。

板子只有一个 CDC 口时（没放 `boot.py`，或放了没硬复位），状态灯显示 `已连接 · 单口·旧模式`，
页面顶部还会常驻一条警告，原文是：

> 旧模式：板子只有一个 CDC 口，设备的 print 与协议字节共用它。把 boot.py 放进 CIRCUITPY 盘并按 RESET 硬复位即可分成两个口；下一版本将不再支持单口模式。

这一版单口还能用（协议和 `print` 挤同一个口，日志口按钮点不动，会提示
"单口板子没有独立的控制台端口…"），但别再往这个形态上投入——下一版只认双口。

断开就再点一次同一个按钮（按钮文字会变成"断开"）。

## 4. 工作台

工作台是主界面，分上下两部分：

- 上面是**引脚池**，平铺板上所有 GP 引脚，每颗芯片显示脚名和能力角标。
- 下面是若干条**功能泳道**：数字输入、数字输出、PWM、ADC、I2C、UART、SPI。

绑定的操作有两种，随你喜好：

| 操作 | 结果 |
| --- | --- |
| 把芯片拖进泳道 | 该脚绑定到那个功能 |
| 点一下芯片，再点泳道 | 同上 |
| 点芯片上的 × | 释放该脚 |
| 把芯片拖回引脚池 | 同上 |

规则只有一条：**一个引脚同一时刻只能属于一个功能**。你把已经做 PWM 的脚拖进 ADC 泳道，
它就从 PWM 那边自动离开——不需要先手动解绑。这个仲裁是固件做的，所以即使两个人同时开
两个页面操作同一块板，也不会出现两边都以为脚是自己的。

所有改动**立即生效并下发到板子**，没有"保存"或"应用"按钮。

### 4.1 数字输入

把脚拖进"数字输入"泳道，芯片上会出现一个小圆点，实时反映该脚电平（亮=高）。

可以再点芯片上的下拉，选上拉 / 下拉 / 无。默认是上拉，也就是说引脚悬空时读到高电平。

电平变化是板子主动推给页面的，所以响应很快。页面每秒还会做一次对账，
万一板子被重启过，配置会自动补发回去。

### 4.2 数字输出

把脚拖进"数字输出"泳道，芯片上出现一个可点的电平块，点一下就翻转高低。

### 4.3 PWM

把脚拖进"PWM"泳道，然后设频率和占空比。

频率输入框旁边有个 ▾ 按钮，点开是一张 1～1000 的预设网格，选完再用右边的单位下拉
（mHz / Hz / kHz / MHz）定数量级。这样"50kHz"就是点 50、选 kHz 两下搞定。

占空比是 0～1 之间的数。

**频率不是想要多少就有多少**。rp2 的硬件 PWM 只能生成 125 MHz/(div×(top+1))，
实测下限是 9 Hz：你填 1、5、8 Hz，板子都跑 9 Hz；高频也会量化（1000→990、2000→2035）。
固件把 slice 真实运行的频率随状态一起回报，界面于是把那个频率框描成琥珀色，
悬停能看到"设定 X Hz，硬件实际 Y Hz"，偏差超过 5% 时还会在日志里写一条。
低于 1 Hz 的值（例如 0.5）不发放，板子直接回 `freq < 1 Hz: PWMOut takes whole hertz`。

**一个坑要提前知道**：rp2 的硬件 PWM 按 slice 分组，一个 slice 只有一台计数器，
**同 slice 的两个脚只能共用一个频率**。分组大致是相邻的偶/奇脚成对：GP0 与 GP1 一个 slice、
GP2 与 GP3 下一个，以此类推；GP24 与 GP25 是 slice 6。
第二个脚如果要求不同的频率，`pwm.cfg` 会失败并回
`RuntimeError: Conflicting settings for shared resource`——固件不会去偷偷改第一个脚的频率，
而是把这个脚退还给引脚池，界面上那条命令会显示失败。需要两个独立频率时，选不相邻的脚
（例如 GP7 与 GP11）。另外同一个 PWM 通道有时还能映射到更高位的脚，两处其实是一个 slice；
拿不准就试一次，冲突会以那条错误明确报出来。

### 4.4 ADC

把脚拖进"ADC"泳道，芯片上直接显示电压。再点那个数字，可以在 V / mV / raw 之间循环切换。

ADC 泳道还接受一颗特殊的 **TEMP** 芯片（在引脚池最末尾），它是芯片内部温度传感器。
默认直接显示摄氏度。它不占用任何物理引脚，可以和其它 ADC 通道同时用。

### 4.5 I2C

I2C、UART 和 SPI 是"总线型"功能，界面不一样：泳道里放的不是单个引脚，而是**总线卡片**。

点泳道底部的"＋ 添加总线"，出现一张卡片，上面有 SDA 和 SCL 两个带标签的槽。
把引脚池里角标为 D 的脚拖进 SDA 槽、角标为 S 的脚拖进 SCL 槽。

拖不进来的时候界面会告诉你原因（这个脚不能当 SCL、或者这两个脚配不成一对），
不会让你点了没反应。

rp2 的 I2C 引脚对是**有讲究的**：SCL 必须是奇数脚，SDA 必须是偶数脚，
而且要满足 `SDA = SCL - 1`（模 4）。比如 GP5+GP4 合法，GP8+GP10 永远配不成。
合法组合板子会主动报上来，所以只要看角标就不会选错。

卡片上还能选时钟频率、扫总线（`扫描` 按钮，列出总线上应答的器件地址）、
做原始事务（填从机地址、写字节、读字节数）。

第一次用建议先点扫描。如果扫出来是空的，多半是没接线或没上拉——
I2C 总线必须有空闲时拉高的上拉电阻，很多传感器模块自带，裸芯片不带。

### 4.6 UART

和 I2C 一样是总线卡片，两个槽：TX 和 RX。

和 I2C 不同的是，**UART 只填一个槽也算数**。只接 TX 就是只发不收，只接 RX 就是只听不发，
都是合理用法。两个都填时才检查它们能不能配成一对。

卡片上能选波特率、手敲十六进制发出去、按字节数读回来。

**一个坑**：

- 能用的 UART 脚是固定的那几组，全双工时 TX 和 RX 必须落在同一路 UART 上。
  看角标 T / R 就不会错。

**GP0/GP1 现在是能用的**。它们确实是 RP2350 UART0 的 TX/RX。单口那会儿实测一用就报
`GP1 in use`（当时它们被 CircuitPython 控制台占着）；换成现在这套双口固件后真机复测：
`uart.cfg tx=0 rx=1` 建总线成功。所以能力表里它们照常出现在
`caps.uart.tx/rx/pairs` 中，引脚池的 GP0/GP1 也会亮出 T / R 角标。

### 4.7 UART 实时终端

光靠卡片上的"读取"按钮看串口数据太累了。所以控制台区上方有一排标签页：
**Console** 是设备输出镜像（没接日志口时是数据口的原始字节，接了以后是控制台口），
每配好一路 UART 就多出 **UART #0**、**UART #1** 这样的标签。

点开某个 UART 标签：

- 板子收到的字节实时打在终端里。
- 你在终端里敲的字符直接发到对应的 TX 上。
- 右上角 **HEX** 按钮切换显示方式：文本模式原样显示，HEX 模式显示成大写十六进制，
  调二进制协议时用这个。

只有当前显示的标签在收数据，切走就停止推送，不浪费带宽。

顶部的清屏 / 复制 / 导出按钮跟着当前标签走：你在 UART 标签里点清屏，清的是那个终端。

### 4.8 SPI

同样是总线卡片，但脚更多：**SCK、MOSI、MISO** 三个数据槽，外加最多四路片选
**CS0..CS3**（数字来自 `caps.spi.max_cs`）。

和 UART 一样允许"半总线"：**缺 MOSI 或缺 MISO 都能配**，只发或只收都是合理用法。
但 **SCK 必须有**，而且至少要再有一个数据脚——只给 SCK 电路不认（实测报
`Must provide MISO or MOSI pin`）。

**这泳道有两处要留意**：

- 数据脚必须**全在同一组里**。RP2350 上实测只有两组：

  | 组 | SCK | MOSI | MISO |
  | --- | --- | --- | --- |
  | 第一组 | 2 / 6 / 18 / 22 | 3 / 7 / 19 / 23 | 0 / 4 / 16 / 20 |
  | 第二组 | 10 / 14 / 26 | 11 / 15 / 27 | 8 / 12 / 24 / 28 |

  跨组就报 `SCK/MOSI/MISO 必须来自同一引脚组（同一硬件 SPI）`，选了也不会绑上。
  两组各只有一路硬件 SPI，所以**同时最多两路总线**，第三路会先被界面挡住
  （`本固件最多支持 {0} 路 SPI 总线`）。

- **片选随便挑**。CS 在这套固件里不是 SPI 外设的一部分，是普通的输出脚，事务期间
  拉低、结束拉高，所以任何空闲 GP 都能当 CS。CS 也算占用：绑上之后 GPIO 泳道就选不到它了。

事务台一次一笔：写(hex) 里填十六进制，读字节 里填要读回几个字节，**片选**下拉选这次
拉哪一路（选"—"表示不动片选），勾上**保持片选**则事务结束后 CS 继续留在低位——
分两段读同一个寄存器时用得上。点**传输**后结果打在下面一行，形如

```
03 14 25  ·  读回 3 字节  ·  实际 1973684 Hz
```

**"实际"这一栏是必要的**：RP2 只能用偶数分频去分 150 MHz 系统时钟，上限 75 MHz。
所以选 2 MHz 板子真正跑出来的是 1973684 Hz，选 10 MHz 是 9375000 Hz，跟 PWM 那个
`hfreq` 一个道理，界面报的是硬件的事实而不是你按下去的数。

## 5. 示波器面板

工作台下方是可折叠的波形区。ADC 泳道里绑了几个脚，这里就出现几个通道按钮
（含 TEMP，最多同时 4 路）。

点"开始采集"，板子改成每 25ms 采一批、攒够一批整批发给页面，画在 canvas 上。

能做的操作：

| 操作 | 效果 |
| --- | --- |
| 滚轮 | 横向缩放，**以光标所在的那个采样点为锚** |
| Shift + 滚轮 | 纵向缩放，锚在光标处的电压 |
| 按住拖动 | 平移时间轴，回看历史 |
| 双击 | 复位成全览 |
| 十字线按钮 | 打开后光标处出现十字线，左上角读出时刻和各路数值 |

两种采集模式：**Roll** 是固定 2048 点连续滚动；**FIFO** 可以选深度（256～4096），
采满就环形覆盖老数据，适合抓一段就停下来的场景。

每个通道能填 `y = k·x + b` 校正值，在 raw 域上生效。TEMP 通道就靠这个把 raw 还原成摄氏度。

通道颜色按引脚固定分配：你把某个通道关掉再打开，它的颜色不会变；
加别的通道也不会把已有通道的颜色挤走。

采集期间，泳道芯片上的读数直接复用波形帧里最新的一行，并且做了平滑，
所以数字不会乱跳，两处显示也不会打架。

## 6. 调试控制台

页面最下方是控制台，两个模式：

- **监听**：只读，镜像设备吐出来的字节。没接日志口时镜像数据口（协议行和设备的 `print`
  混在一起）；接上日志口后镜像的是控制台口，横幅、`print`、异常回溯都在那里，
  协议行不再刷屏。
- **REPL**：可写，你的键盘直接透传给板子的 CircuitPython 提示符。想临时试一段代码用这个。

**连接日志口**按钮负责接进控制台口。双口板子在握手后页面会自己把它挂上（探测已授权的端口，
认那个不应答协议 ping 的），你不需要动手；只有当初没给第二个口授权时才需要点一次，
此时状态灯会显示 `日志口未连接`。接上后按钮变灰并显示"日志口已连接"，断开设备前不能再换。

**协议流**按钮是开关：打开后连协议端口的原始 JSON/二进制字节也写进终端，
默认关闭——那些字节界面已经解析过了，开着只会和日志口的输出混在一起。想对着原始帧查协议才按它。

按钮切换模式。切到 REPL 时，任何开着的 UART 标签会自动让位给 Console：板子的 REPL
就在控制台口上，一个口只允许一个使用者。要说清楚的是双 CDC 到底省了什么：
REPL 只动控制台口，**数据口的连接不会被断开**，所以退出 REPL 不用重新选端口、重新授权；
但进入 REPL 的 `Ctrl+C` 会把 `code.py` 停掉，因此 REPL 期间协议是**真的没人应答**的，
所有泳道都不可用（详见 [03 使用示例](../03_Sample_Program_User_Guide/README.md) 第 9 节）。
切回监听时页面会重启设备程序并重新握手（板子的易失配置清零，页面随后自动重新下发）。

三个操作按钮：清屏、复制全部、导出为 txt 文件。

## 7. 界面设置

- 右上角 **EN / 中文** 按钮切换语言，选择会记住。
- 你绑的引脚、设的频率、总线配置、波形通道选择，全都存在浏览器本地。
  关掉页面再打开会自动恢复，连上板子后自动下发。
- 顶部**配置 ▾**菜单把这份本地配置摆到明面上：
  - **导出配置**：把当前配置写成 `picoharness-config-<时间戳>.json` 下载走，
    控制台会打出 `已导出 <文件名>`。换电脑、备份、给同事复制板子配置都靠它。
  - **导入配置**：选一个这样的 JSON 文件，配置立刻替换并下发，
    控制台打 `已导入 {n} 项配置`。不是这个格式的文件会被拒掉（`导入失败: …`）。
  - **清空配置**：会先弹确认框（"清空本地保存的全部配置？…"），确认后引脚、PWM、
    总线全部回到未分配，并把浏览器里存的那份一起清掉。
  - 菜单底部那行小字就是重点：**配置存在浏览器里，不在板子里**。
- 想绕过菜单直接清，也可以在浏览器控制台里执行 `localStorage.clear()` 再刷新。

导入的配置不一定适合眼前这块板：**连接状态下的握手会拿设备报上来的能力表核对一遍绑定**，
把这块固件带不动的脚解除掉，并按功能在控制台点名，例如
`本固件不支持这些 PWM 脚，已解除绑定: GP1 GP2`、`这些引脚不符合本固件的 UART 配对规则，已解除绑定: GP10`。
被点名的脚回到引脚池，卡片还在，你换个合法的脚补上就行。离线导入不做这个核对，
连上板子时同样会补一次。

注意：配置存在**浏览器**里，不在板子里。换台电脑就得重新配。
板子断电重启后自身配置是清零的，靠页面这边每秒的对账轮询补发回去。

## 8. 硬件注意事项汇总

这些是踩过的坑，写在这里省你的时间。

| 事项 | 说明 |
| --- | --- |
| PWM 同 slice 共频 | 同一 slice 两个脚改频率会互相覆盖，需要独立频率就换脚 |
| PWM 频率下限 | 硬件只接受整数 Hz，实测最低 9 Hz（1..8 Hz 都跑 9）。低于 1 Hz 板子直接报错；1..8 由固件回报真实频率，界面把频率框标琥珀并写日志 |
| I2C 必须有上拉 | 空闲时两线不拉高就报 `No pull up found`，这是接线问题不是软件问题 |
| I2C 引脚对固定 | SCL 奇、SDA 偶、`SDA = SCL-1 (mod 4)`，看角标 S/D 即可 |
| UART GP0/GP1 | 早先单口形态实测被 CircuitPython 控制台占用（`GP1 in use`）；0.1.14 双口固件实测可用，能力表已把它们算进 UART0 |
| UART 引脚固定 | 只有特定脚能做 TX/RX，全双工时两脚须在同一路 UART |
| SPI 数据脚分组 | SCK/MOSI/MISO 必须来自同一组（见 4.8 的表），跨组建不起来；两组=两路总线 |
| SPI 时钟取整 | 时钟只能 150 MHz 除以偶数，上限 75 MHz。实测请求 2 MHz 实跑 1973684 Hz、10 MHz 实跑 9375000 Hz，界面在事务结果里写"实际 {0} Hz" |
| SPI 片选是普通 IO | CS 由固件当输出脚驱动，不占硬件 SPI 资源，但会占一个 GP |
| 复制 code.py 会重启板子 | 浏览器串口连接会断，需要手动重连 |
| 改 boot.py 要硬复位 | 按 RESET 或拔插 USB；Ctrl-D 软重启不会重跑 boot.py，端口还是一个 |
| 两个 COM 口分不清 | 共用同一 VID/PID，页面靠 nonce ping 认口；手工排查时发一条 `{"cmd":"ping"}` 看谁回 |
| 换板子 | 能力表是探测出来的，界面自动适配，不用改代码 |

## 9. 连不上怎么办

按顺序检查：

1. **板子上电了吗** — CIRCUITPY 卷在不在？不在就重烧 UF2。
2. **code.py 在根目录吗** — 文件名必须是 `code.py`，不能放在子目录里。
3. **boot.py 在吗、硬复位过吗** — 只有一个 CDC 口说明双口没打开；
   按一次 RESET 再看设备管理器是否变成两个 COM 口。
4. **装 asyncio 了吗** — 打开**控制台口**看板子输出，`ImportError: no module named 'asyncio'`
   就是缺库，回 2.2 节。
5. **浏览器对吗** — 必须桌面版 Chrome 或 Edge，Firefox 和 Safari 不支持 Web Serial。
6. **两个口都授权了吗** — 选择框里同名的条目要全选，否则日志口/REPL 接不上，
   页面只能靠"踢一脚"重启设备。
7. **串口被占了吗** — 如果 Thonny、mpremote 或别的串口工具开着这两个 COM 口，先关掉。
8. **弹不出选择框** — 点的是"连接设备"吗？地址栏右侧有没有被拦截的权限提示？
9. **提示"找不到协议口"** — 板上的程序没在跑，也不应答 kick。用控制台口进 REPL，
   手敲 `import code` 看真实报错。

还不行，翻到 [03 使用示例](../03_Sample_Program_User_Guide/README.md) 的报错对照表，
或者直接开串口工具看板子吐了什么。
