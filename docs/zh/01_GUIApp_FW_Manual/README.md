# PicoHarness 使用手册

这份手册带你从零跑起 PicoHarness，并逐个功能讲清楚怎么用。
只关心"怎么把线接上、把界面点开"的话，读完这一篇就够了。
协议细节请看 [02 协议参考](../02_Library_User_Guide/README.md)，具体玩法和报错对照请看 [03 使用示例](../03_Sample_Program_User_Guide/README.md)。

---

## 1. PicoHarness 是什么

一块 Pico 开发板 + 一个网页，就是一台桌面测试治具。

- PC 侧交付物是**单个 HTML 文件**，双击就能用，不用装 Python、不用装驱动、不用起服务。
- 网页通过浏览器的 **Web Serial API** 直连 Pico 的 USB 串口。
  板子上有两个 CDC 口：数据口跑网页与板子之间的 JSON 协议，控制台口归 CircuitPython，
  管 `print`、异常回溯和 REPL。页面会自动认出口色，不用你猜 COM 号。
- 板子上跑一个 CircuitPython `code.py`，收 JSON 命令、控制引脚、把读数推回来。

能做什么：给引脚通断、量电压、出 PWM、扫 I2C 总线、发串口，顺便带一个示波器面板和一个能敲命令的调试控制台。

已验证环境：Raspberry Pi Pico 2（rp2350a）、CircuitPython 10.3.1、桌面版 Chrome / Edge。

## 2. 准备板子

### 2.1 烧 CircuitPython

去 <https://circuitpython.org/board/raspberry_pi_pico2/> 下载 UF2（用别的板子就换对应页面）。

1. 板子断电：拔掉 USB 线。
2. 按住板上的 BOOTSEL 按钮，把 USB 线插回电脑，松开按钮。
3. 电脑上会出现一个名为 `RPI-RP2` 的 U 盘。
4. 把 `.uf2` 文件拖进这个 U 盘。板子会自动重启。
5. 重启后出现名为 `CIRCUITPY` 的 U 盘，说明烧写成功。

### 2.2 装固件依赖

`code.py` 的事件循环需要 `asyncio` 库，而 CircuitPython 不内置它。缺了会在串口终端报
`ImportError: no module named 'asyncio'`。

最省事的做法是用 circup（在电脑上装一次即可）：

```bash
pip install circup
circup install asyncio
```

circup 会自动把 `asyncio` 和它依赖的 `adafruit_ticks` 装进 CIRCUITPY 卷的 `lib/` 目录，
版本也会匹配你的 CircuitPython。

不想装 circup 的话，手动下载 [Library Bundle](https://circuitpython.org/libraries)，
把里面的 `asyncio` 目录和 `adafruit_ticks.mpy` 复制到 `CIRCUITPY/lib/`。

PIO 那台 PWM 发生器还要 `adafruit_pioasm`（`circup install adafruit_pioasm`，或把仓库里备好的
`src/fw/lib/adafruit_pioasm.mpy` 复制进 `CIRCUITPY/lib/`）。它**不是致命缺件**：`rp2pio` 已经编进
RP2 的固件里，只有拼装 PIO 文本的 `adafruit_pioasm` 要外挂，没有它 `code.py` 照跑，
只是 `caps` 里不出现 `pwm_pio`，界面上也就没有 HW / PIO 这个选择，PWM 仍能用硬件 slice。

### 2.3 放固件

固件是两个文件，都复制到 CIRCUITPY 卷的根目录，覆盖同名文件：

- `src/fw/boot.py`：只做一件事——`usb_cdc.enable(console=True, data=True)`，
  把 USB 串口拆成"控制台口"和"数据口"两个。
- `src/fw/code.py`：治具本体，收 JSON 命令、控制引脚、把读数推回来。

`boot.py` **只在硬复位后生效**：按板上的 RESET 键，或拔插一次 USB。
Ctrl-D 软重启不会重跑它，所以拷完记得硬复位一次——设备管理器里出现两个 COM 口才算成功。

如果根目录里有 `main.py`，把它删掉或改名：CircuitPython 只运行 `main.py`，
有了它就不会碰 `code.py`。

复制完成，板子会自动重启并开始运行。这一步不需要在电脑上装任何东西。

> 以后每次换了 `code.py`，都是同一个动作：复制过去，板子自动重启。
> 重启会断开浏览器那边的串口连接，重连一下就行。换 `boot.py` 要多一步硬复位。

## 3. 打开上位机

拿到 `dist/index.html`（自己构建的方法见 [04 构建指南](../04_FW_Build_Guide.txt)），
双击用 Chrome 或 Edge 打开。`file://` 直开就能用，不需要起本地服务器。

点页面顶部的**连接设备**。两个 CDC 口共用同一厂商/产品 ID，浏览器给不出名字，
所以页面靠"问"来认口：给每个已授权的端口**同时**发一条 ping，只有回了随机数的那个是数据口；
结论会缓存 4 秒，所以断开再重连基本是瞬间的事。

- 第一次用：浏览器弹串口选择框，把列出的板子条目**全部选中**（一般显示为
  `USB Serial Device` 或带 `2E8A` 厂商 ID 的项，双口会有两条），授权之后就不再弹框。
- 以后重开页面：直接零点击重连，端口已经授权过了。
- 板子上的程序没在跑（停在 REPL 或崩了）：页面会在**有设备输出的那个口**上补一发
  `Ctrl+C` + `Ctrl+D` 把它踢起来，然后再认一次口。数据口不吃控制字节，
  所以踢错了口是唤不醒板子的——这也是页面按"谁的动静大"来挑候选的原因。
  此时不会再弹第二次选择框：已授权的端口都不应答，只是 `code.py` 没在跑而已。

握手拿到的是设备自己报上来的能力表，不重启板子（`hello` 命令）。

连接成功后：

- 顶部状态灯变绿，文字形如 `已连接 · 双口 · 日志口 ✓`。第二段告诉你板子是真双口
  还是 `单口·旧模式`；第三段是日志口的状态，`日志口未连接` 时手点一下**连接日志口**即可。
  双口板子在握手后会自动去挂日志口，成功就不需要你动手。
- 下方控制台打出握手信息。
- 工作台的引脚芯片上会出现能力角标（P=PWM、A=ADC、S/D=I2C、T/R=UART、CK/DO/DI=SPI），
  逐条解释见 [§4.1 角标怎么看](#41-角标怎么看)。

那些角标是**板子自己报上来的**，不是写死在页面里的。所以换一块板子、
或者某个脚被占用，界面上会如实反映，不会出现"看着能用其实不能用"。

板子只有一个 CDC 口时（没放 `boot.py`，或放了没硬复位），状态灯显示 `已连接 · 单口·旧模式`，
页面顶部还会常驻一条警告，原文是：

> 旧模式：板子只有一个 CDC 口，设备的 print 与协议字节共用它。把 boot.py 放进 CIRCUITPY 盘并按 RESET 硬复位即可分成两个口；下一版本将不再支持单口模式。

这一版单口还能用（协议和 `print` 挤同一个口，日志口按钮点不动，会提示
"单口板子没有独立的控制台端口…"），但别再往这个形态上投入——下一版只认双口。

断开就再点一次同一个按钮（按钮文字会变成"断开"）。

顶部还有一个**重启板子**，鼠标悬上去是"等同于按 RESET：重跑 boot.py，链路会断，重连后界面会重新下发配置"。
它发的就是 `reset` 命令：板子先把回执发出来，四分之一秒后 `microcontroller.reset()`，效果和你走到板子前
按一下 RESET 完全一样——**只有硬复位才重跑 `boot.py`**，浏览器里的软复位（Ctrl-D）不会，所以这一步
存在的理由就是"拷完 `boot.py` 不必碰板子"。点下去前先弹确认框，原文是
"重启板子？串口链路会断开，板子上正在跑的 PWM、总线等即时配置会清空；等它起来后在界面重新点"连接设备"。"
复位之后链路是断的，等几秒钟重新点**连接设备**就行。按钮和 Ping / Echo 共用一条规则：链路就绪、
且控制台停在**监控**模式时才可点。

两种情况它帮不上忙：板子根本没在跑 `code.py`（停在 REPL 或崩了）——那时靠的是上面连接流程里的
`Ctrl+C` + `Ctrl+D` 唤醒；以及固件版本还没有 `reset` 命令——确认后控制台会打
`重启请求失败: unknown cmd: reset`，说明 G: 上那份 `code.py` 是旧的，去拷新的再按一次 RESET。

## 4. 工作台

工作台是主界面，分上下两部分：

- 上面是**引脚池**，平铺板上所有**能从 `board` 取到**的 GP 引脚，每颗芯片显示脚名和能力角标。
  名单来自设备开机时上报的 `caps.gp`（见 [02 §2.0](../02_Library_User_Guide/README.md)）。
  池子可能有洞：Pico 2 W 上 GP23/GP24/GP25 归 CYW43，板级表没声明它们，池子里就没有。
  反过来 GP29 虽然从不以 "GP29" 出现（只叫 `A3` / `VOLTAGE_MONITOR`），固件按 ADC 通道
  别名把它的号码算了出来，所以它在池子里——池子里没有的脚，界面就不会给你拖。
- 下面是若干条**功能泳道**：数字输入、数字输出、PWM、ADC、I2C、UART、SPI。

### 4.1 角标怎么看

角标就是把设备上报的 caps 表逐脚摊开，一个字母对应一张表：

| 角标 | 含义 | 来自哪张表 |
| --- | --- | --- |
| `P` | 固件 PWM 能力表收录了这个脚 | `caps.pwm` |
| `A` | 这个脚能做 ADC 读取 | `caps.adc` |
| `S` | 只能做 I2C 的 SCL：奇数脚 | `caps.i2c_pairs` |
| `D` | 只能做 I2C 的 SDA：偶数脚 | `caps.i2c_pairs` |
| `T` | 能做 UART 的 TX：偶数脚 | `caps.uart.tx` |
| `R` | 能做 UART 的 RX：奇数脚 | `caps.uart.rx` |
| `CK` | 能做 SPI 的 SCK | `caps.spi.groups` 里某一组的 `sck` |
| `DO` | 能做 SPI 的 MOSI，主控发出 | `caps.spi.groups` 里某一组的 `mosi` |
| `DI` | 能做 SPI 的 MISO，主控读入 | `caps.spi.groups` 里某一组的 `miso` |

把鼠标停在角标上就有提示，文案就是上表那句话，例如
`CK = 能做 SPI 的 SCK（caps.spi.groups 里某一组的 sck）`。

四条容易误读的地方：

- **没有某个角标不等于这个脚不能用**。设备没上报那张表，对应的字母就整批不出现——
  旧固件里没有 `caps.spi`，于是一片 CK/DO/DI 都不会亮，但 SPI 泳道照样按设备的答复办事。
  看到角标变少，先确认 `caps` 里那张表在不在。
- 角标说的是"这只脚在某条总线上站哪条线"，不是"它只能干这个"。一颗芯片可以同时是 `P A D T`。
- SPI 的 `CK/DO/DI` 一颗芯片上最多出现一个（rp2 的 SPI 功能表每行只落一个角色）。
  **CS 没有角标**：固件把 CS 当普通输出脚做，任何空闲的 GP 都能当 CS。
- 角标不体现"组"这件事。`CK` 只说明这只脚能做某个组的时钟线；两个脚配不配得到一组，
  点空槽看池子高亮最准——亮起的都能进，变暗的会被固件拒。

绑定的操作有两种，随你喜好：

| 操作 | 结果 |
| --- | --- |
| 把芯片拖进泳道 | 该脚绑定到那个功能 |
| 点一下芯片，再点泳道 | 同上 |
| 点芯片上的 × | 释放该脚 |
| 把芯片拖回引脚池 | 同上 |
| 点总线卡片里的**空槽**，再点一颗亮芯片 | 同上，且这一下不用你先记住谁能进 |

规则只有一条：**一个引脚同一时刻只能属于一个功能**。你把已经做 PWM 的脚拖进 ADC 泳道，
它就从 PWM 那边自动离开——不需要先手动解绑。这个仲裁是固件做的，所以即使两个人同时开
两个页面操作同一块板，也不会出现两边都以为脚是自己的。

所有改动**立即生效并下发到板子**，没有"保存"或"应用"按钮。

总线泳道还有个反向的用法：点卡片里一只**空槽**，池子会反过来告诉你谁能进——能进这只槽的脚
全部亮起，进不去的变暗，提示写的是 `已选中 SCL 槽 — 点击亮起的 GP 芯片即可绑定，变暗的引脚
会被固件拒绝；点空白处取消`。第二下点亮的芯片就完成绑定；点空白处取消聚焦；槽里已经有脚时
点它是解绑，不是聚焦。判定用的就是拖放时同一张 caps 表，所以点亮的一定进得去——
I2C 会按序对算（SCL=GP29 时只有同一外设那一侧的偶数脚亮），UART 会按实例算
（TX=GP28 之后 RX 只剩 1/3/13/15/17/19/29，GP27 是另一路 UART，界面直接把它按暗）。

### 4.2 数字输入

把脚拖进"数字输入"泳道，芯片上会出现一个小圆点，实时反映该脚电平（亮=高）。

可以再点芯片上的下拉，选上拉 / 下拉 / 无。默认是上拉，也就是说引脚悬空时读到高电平。

电平变化是板子主动推给页面的，所以响应很快。页面每秒还会做一次对账，
万一板子被重启过，配置会自动补发回去。

### 4.3 数字输出

把脚拖进"数字输出"泳道，芯片上出现一个可点的电平块，点一下就翻转高低。

### 4.4 PWM

把脚拖进"PWM"泳道，然后设频率和占空比。

频率输入框旁边有个 ▾ 按钮，点开是一张 1～1000 的预设网格，选完再用右边的单位下拉
（mHz / Hz / kHz / MHz）定数量级。这样"50kHz"就是点 50、选 kHz 两下搞定。

占空比是 0～1 之间的数。

**频率不是想要多少就有多少**。rp2 的硬件 PWM 只能生成 125 MHz/(div×(top+1))，
实测下限是 9 Hz：你填 1、5、8 Hz，板子都跑 9 Hz；高频也会量化（1000→990、2000→2035）。
固件把 slice 真实运行的频率随状态一起回报，界面于是把那个频率框描成琥珀色，
悬停能看到"设定 X Hz，硬件实际 Y Hz"，偏差超过 5% 时还会在日志里写一条。

#### 4.4.1 HW / PIO：两种发生器自己选

频率框左边是 **HW | PIO** 两个按钮（只在固件上报了 `caps.pwm_pio` 时出现），
它们决定这一路由什么硬件产生波形：

| | HW = 硬件 PWM slice | PIO = 状态机自己数 |
| --- | --- | --- |
| 频率窗口 | 1 – 30,000,000 Hz | 0.0174553 – 15,000,000 Hz |
| 慢到什么程度 | 实测 1～8 Hz 全都跑 9 Hz | 实测 0.1 Hz 一路稳跑（回报 0.099986 Hz） |
| 占用 | 同 slice 的两个脚共用一个频率 | 每路独占一个状态机，RP2350 一共 12 个 |
| 引脚 | `caps.pwm` | `caps.pwm_pio.pins`（RP2350 每个 GPIO 都有 PIO 矩阵） |

两个窗口的端点**都不是写死在界面里的**：下限是 `clk_min / (2×counters + fixed_cycles)`
= 2288/(2×65535+8) = 0.0174553 Hz，上限是 `clk_max / (fixed_cycles + 2)` = 150 MHz/10
= 15 MHz，五个数全部来自板子的 `caps.pwm_pio`。换一颗芯片、改一段指令，界面跟着变。
输入超出窗口时会被夹回窗口边上，夹的方向永远朝里——0.0174553 这种端点如果按四舍五入落到
0.017455，固件就要按"时钟低于下限"退回，所以界面向内取整。

PIO 这一路的频率框照样会描琥珀色：它回报的是 `SM 时钟 / 一个周期的 tick 数`，
也就是脚上真正出现的频率，不是你填的那个数。12 路同时开是实测过的
（GP0～GP11 各 0.1 Hz、各 50 %，全部正常输出）；第 13 路会被拒：

```
RuntimeError: no free PIO state machine (12/12 in use)
```

这条错误只写在那一颗芯片上（框下方红字 + 日志一行），别的脚不受影响；界面不会替你
把这一路改回 HW——那个选择是你的，状态回报里的 `cfg_pio_pwm` 会诚实地显示板子上到底是
哪几路在跑 PIO。释放任意一路（拖回池中或点 ×）后再点一次 PIO 就能补上。

切发生器时这一路的频率会被夹进新窗口（HW→PIO 不会把频率拉低，PIO→HW 会把 0.1 Hz 抬到
1 Hz），并且固件一定会把这台发生器拆了重建：一个正在跑的状态机仍在照它那条 4 深的
TX FIFO 出货，直接写新数值要等五个周期才见效，所以 `pwm.cfg` 对 PIO 通道一律
`deinit` + 重新 `arm`，第一个周期就是新参数。

**一个坑要提前知道**：rp2 的硬件 PWM 按 slice 分组，一个 slice 只有一台计数器，
**同 slice 的两个脚只能共用一个频率**。分组是数据手册 / pico-sdk `gpio.h` 里 F4 那一列写死的，
不是"相邻两脚"这么含糊：脚号 `n` 落在 slice `S`、通道 `A/B` 上，
- `n` ≤ 31：`S = (n // 2) mod 8`，偶数脚是 A 通道、奇数脚是 B 通道；
- `n` ≥ 32（QFN-80 才有）：`S = 8 + ((n - 32) mod 8) // 2`，仍然偶 A 奇 B。

所以 GP0/GP1 是 slice 0，GP2/GP3 是 slice 1，一路到 GP14/GP15 是 slice 7；
**从 GP16 开始绕回来**：GP16/GP17 又是 slice 0，GP18/GP19 是 slice 1……
GP24/GP25 是 slice 4，GP28/GP29 是 slice 6。这就是"同一个通道有时还能映射到更高位的脚，
两处其实是一个 slice"的来源——查表算一遍就知道，不用试。
第二个脚如果要求不同的频率，`pwm.cfg` 会失败并回
`RuntimeError: Conflicting settings for shared resource`——固件不会去偷偷改第一个脚的频率，
而是把这个脚退还给引脚池，界面上那条命令会显示失败。需要两个独立频率时，选算出来不同 slice 的脚
（例如 GP7 是 slice 3、GP11 是 slice 5），**或者干脆把其中一路切到 PIO**：
PIO 数的是自己的 tick，跟 slice 分组没有关系。

### 4.5 ADC

把脚拖进"ADC"泳道，芯片上直接显示电压。再点那个数字，可以在 V / mV / raw 之间循环切换。

**哪些脚能当 ADC 是封装决定的**，pico-sdk `platform_defs.h` 和 `gpio.h` 都写明了：
RP2350A（QFN-60，Pico 2 / Pico 2 W 用的就是这颗）是 **GP26..GP29**（ADC0..ADC3），
RP2350B（QFN-80）是 **GP40..GP47**（ADC0..ADC7）。板级表没声明的脚不会出现；而 Pico 2
上实测 GP29 是在池子里的——它只以 `A3` / `VOLTAGE_MONITOR` 出现，固件按 ADC 通道别名
算出号码，`caps.adc` 因此是 GP26/GP27/GP28/GP29 加上内部温度那颗虚拟通道。
按 Pico 2 数据手册第 8 页，GP29 本是"IP 以 ADC 模式测 VSYS/3"的脚，实测读上来约
1.600 V（raw 31815），也就是 VSYS≈4.80 V；你要拿它接外部信号就得先接受它读的是板载电源。
界面按 `caps.adc` 点亮角标，所以换板子/换构建都不用改代码。

ADC 泳道还接受一颗特殊的 **TEMP** 芯片（在引脚池最末尾），它是芯片内部温度传感器。
默认直接显示摄氏度。它不占用任何物理引脚，可以和其它 ADC 通道同时用。

### 4.6 I2C

I2C、UART 和 SPI 是"总线型"功能，界面不一样：泳道里放的不是单个引脚，而是**总线卡片**。

点泳道底部的"＋ 添加总线"，出现一张卡片，上面有 SDA 和 SCL 两个带标签的槽。
把引脚池里角标为 D 的脚拖进 SDA 槽、角标为 S 的脚拖进 SCL 槽。

拖不进来的时候界面会告诉你原因（这个脚不能当 SCL、或者这两个脚配不成一对），
不会让你点了没反应。

rp2 的 I2C 引脚对是**有讲究的**：走的是硬件 DW_apb_i2C 外设（不是 PIO），全片两路实例，
`gpio.h` 的 F3 列决定了规矩 —— **SCL 必须是奇数脚，SDA 必须是偶数脚，且 `SDA ≡ SCL - 1`（模 4）**。
比如 GP5+GP4 合法，GP13+GP4 也合法（配对不要求两脚相邻，只要模 4 同余），
而 GP8+GP10 永远是错的——两个都是偶数脚，谁都当不了 SCL。
属于哪一路实例也是脚号算出来的：`(n // 2) mod 2`，0 是 i2c0、1 是 i2c1；
上面那条模 4 的条件本身就保证了 SCL 和 SDA 落在同一路，所以配对规则里没有额外的实例检查。
CircuitPython 只在满足条件的组合上建得起总线，
否则直接 `Invalid pins`；能力表 `caps.i2c_pairs` 就是按这条规则穷举、再让固件真建一次确认的有序对，
界面照着它点角标，所以看角标就不会选错。时钟频率超过 1 MHz 会被 CP 拒绝。

卡片上还能选时钟频率、扫总线（`扫描` 按钮，列出总线上应答的器件地址）、
做原始事务（填从机地址、写字节、读字节数）。

第一次用建议先点扫描。如果扫出来是空的，多半是没接线或没上拉——
I2C 总线必须有空闲时拉高的上拉电阻，很多传感器模块自带，裸芯片不带。

### 4.7 UART

和 I2C 一样是总线卡片，两个槽：TX 和 RX。

和 I2C 不同的是，**UART 只填一个槽也算数**。只接 TX 就是只发不收，只接 RX 就是只听不发，
都是合理用法。两个都填时才检查它们能不能配成一对。

卡片上能选波特率、手敲十六进制发出去、按字节数读回来。

**一个坑**：

- 能用的 UART 脚是**固定的**：偶数脚都能当 TX，奇数脚都能当 RX（`gpio.h` 的 F2 / F11 两列），
  但一个脚走哪一路 UART 由数据手册的表决定 —— CircuitPython 用的公式是
  `instance = ((n + 4) // 8) mod NUM_UARTS`，rp2 上 `NUM_UARTS = 2`。
  所以全双工时 TX 和 RX 必须算出同一路，否则 `Invalid pins`。
  看角标 T / R 不会错，卡片只在两脚配不成一路时才拦你。

**GP0/GP1 现在是能用的**。它们确实是 RP2350 UART0 的 TX/RX。单口那会儿实测一用就报
`GP1 in use`（当时它们被 CircuitPython 控制台占着）；换成现在这套双口固件后真机复测：
`uart.cfg tx=0 rx=1` 建总线成功。所以能力表里它们照常出现在
`caps.uart.tx/rx/pairs` 中，引脚池的 GP0/GP1 也会亮出 T / R 角标。

### 4.8 UART 实时终端

光靠卡片上的"读取"按钮看串口数据太累了。所以控制台区上方有一排标签页：
**Console** 是设备输出镜像（没接日志口时是数据口的原始字节，接了以后是控制台口），
每配好一路 UART 就多出 **UART #0**、**UART #1** 这样的标签。

点开某个 UART 标签：

- 板子收到的字节实时打在终端里。
- 你在终端里敲的字符直接发到对应的 TX 上。
- 右上角 **HEX** 按钮切换显示方式：文本模式原样显示，HEX 模式显示成大写十六进制，
  调二进制协议时用这个。

只有当前显示的标签在收数据，切走就停止推送，不浪费带宽。

顶部的清屏 / 复制 / 导出按钮跟着当前标签走：你在 UART 标签里点清屏，清的是那个终端。

### 4.9 SPI

同样是总线卡片，但脚更多：**SCK、MOSI、MISO** 三个数据槽，外加最多四路片选
**CS0..CS3**（数字来自 `caps.spi.max_cs`）。

芯片角标里的 `CK/DO/DI` 就是这三个数据角色（见 [§4.1 角标怎么看](#41-角标怎么看)）。
**CS 没有角标**：固件把片选当普通输出脚来做，任何空闲的 GP 都能当 CS。

和 UART 一样允许"半总线"：**缺 MOSI 或缺 MISO 都能配**，只发或只收都是合理用法。
但 **SCK 必须有**，而且至少要再有一个数据脚——只给 SCK 电路不认（实测报
`Must provide MISO or MOSI pin`）。

**这泳道有两处要留意**：

- 数据脚必须**全在同一组里**，一组对应一路硬件 SPI。RP2350 只有两路，所以是两组：

  | 组 | SCK | MOSI(TX) | MISO(RX) |
  | --- | --- | --- | --- |
  | SPI0 | 2 / 6 / 18 / 22 / **34 / 38** | 3 / 7 / 19 / 23 / **35 / 39** | 0 / 4 / 16 / 20 / **32 / 36** |
  | SPI1 | 10 / 14 / 26 / **30 / 42 / 46** | 11 / 15 / 27 / **31 / 43 / 47** | 8 / 12 / 24 / 28 / **40 / 44** |

  这张表是 `gpio.h` F1 列的完整转录，其中加粗的 30..47 只有 QFN-80（RP2350B）封装才有；
  你的板子实际能用哪些脚取决于板级定义声不声明那个脚，固件开机时把这张表**投影到 `caps.gp`**
  再交给界面，所以不写死任何脚号。Pico 2 W 就是个活例子：它的 `pins.c` 没声明 GP23，
  投影之后 `caps.spi.groups[0].mosi` 只剩 `3 / 7 / 19`（这是板级定义表和投影规则的结论，不是实测）。
  跨组就报 `SCK/MOSI/MISO 必须来自同一引脚组（同一硬件 SPI）`，选了也不会绑上。
  两组各只有一路硬件 SPI，所以**同时最多两路总线**，第三路会先被界面挡住
  （`本固件最多支持 {0} 路 SPI 总线`）。

- **片选随便挑**。CS 在这套固件里不是 SPI 外设的一部分，是普通的输出脚，事务期间
  拉低、结束拉高，所以任何空闲 GP 都能当 CS。CS 也算占用：绑上之后 GPIO 泳道就选不到它了。

事务台一次一笔：写(hex) 里填十六进制，读字节 里填要读回几个字节，**片选**下拉选这次
拉哪一路（选"—"表示不动片选），勾上**保持片选**则事务结束后 CS 继续留在低位——
分两段读同一个寄存器时用得上。点**传输**后结果打在下面一行，形如

```
03 14 25  ·  读回 3 字节  ·  实际 1973684 Hz
```

**"实际"这一栏是必要的**：RP2 只能用偶数分频去分 150 MHz 系统时钟，上限 75 MHz。
所以选 2 MHz 板子真正跑出来的是 1973684 Hz，选 10 MHz 是 9375000 Hz，跟 PWM 那个
`hfreq` 一个道理，界面报的是硬件的事实而不是你按下去的数。

## 5. 示波器面板

工作台下方是可折叠的波形区。ADC 泳道里绑了几个脚，这里就出现几个通道按钮
（含 TEMP，最多同时 4 路）。

点"开始采集"，板子改成每 25ms 采一批、攒够一批整批发给页面，画在 canvas 上。

能做的操作：

| 操作 | 效果 |
| --- | --- |
| 滚轮 | 横向缩放，**以光标所在的那个采样点为锚** |
| Shift + 滚轮 | 纵向缩放，锚在光标处的电压 |
| 按住拖动 | 平移时间轴，回看历史 |
| 双击 | 复位成全览 |
| 十字线按钮 | 打开后光标处出现十字线，左上角读出时刻和各路数值 |

两种采集模式：**Roll** 是固定 2048 点连续滚动；**FIFO** 可以选深度（256～4096），
采满就环形覆盖老数据，适合抓一段就停下来的场景。

每个通道能填 `y = k·x + b` 校正值，在 raw 域上生效。TEMP 通道就靠这个把 raw 还原成摄氏度。

通道颜色按引脚固定分配：你把某个通道关掉再打开，它的颜色不会变；
加别的通道也不会把已有通道的颜色挤走。

采集期间，泳道芯片上的读数直接复用波形帧里最新的一行，并且做了平滑，
所以数字不会乱跳，两处显示也不会打架。

## 6. 调试控制台

页面最下方是控制台，两个模式：

- **监听**：只读，镜像设备吐出来的字节。没接日志口时镜像数据口（协议行和设备的 `print`
  混在一起）；接上日志口后镜像的是控制台口，横幅、`print`、异常回溯都在那里，
  协议行不再刷屏。
- **REPL**：可写，你的键盘直接透传给板子的 CircuitPython 提示符。想临时试一段代码用这个。

**连接日志口**按钮负责接进控制台口。双口板子在握手后页面会自己把它挂上（探测已授权的端口，
认那个不应答协议 ping 的），你不需要动手；只有当初没给第二个口授权时才需要点一次，
此时状态灯会显示 `日志口未连接`。接上后按钮变灰并显示"日志口已连接"，断开设备前不能再换。

**协议流**按钮是开关：打开后连协议端口的原始 JSON/二进制字节也写进终端，
默认关闭——那些字节界面已经解析过了，开着只会和日志口的输出混在一起。想对着原始帧查协议才按它。

按钮切换模式。切到 REPL 时，任何开着的 UART 标签会自动让位给 Console：板子的 REPL
就在控制台口上，一个口只允许一个使用者。要说清楚的是双 CDC 到底省了什么：
REPL 只动控制台口，**数据口的连接不会被断开**，所以退出 REPL 不用重新选端口、重新授权；
但进入 REPL 的 `Ctrl+C` 会把 `code.py` 停掉，因此 REPL 期间协议是**真的没人应答**的，
所有泳道都不可用（详见 [03 使用示例](../03_Sample_Program_User_Guide/README.md) 第 10 节）。
切回监听时页面会重启设备程序并重新握手（板子的易失配置清零，页面随后自动重新下发）。

三个操作按钮：清屏、复制全部、导出为 txt 文件。

## 7. 界面设置

- 右上角 **EN / 中文** 按钮切换语言，选择会记住。
- 你绑的引脚、设的频率、总线配置、波形通道选择，全都存在浏览器本地。
  关掉页面再打开会自动恢复，连上板子后自动下发。
- 顶部**配置 ▾**菜单把这份本地配置摆到明面上：
  - **导出配置**：把当前配置写成 `picoharness-config-<时间戳>.json` 下载走，
    控制台会打出 `已导出 <文件名>`。换电脑、备份、给同事复制板子配置都靠它。
  - **导入配置**：选一个这样的 JSON 文件，配置立刻替换并下发，
    控制台打 `已导入 {n} 项配置`。不是这个格式的文件会被拒掉（`导入失败: …`）。
  - **清空配置**：会先弹确认框（"清空本地保存的全部配置？…"），确认后引脚、PWM、
    总线全部回到未分配，并把浏览器里存的那份一起清掉。
  - 连上的固件带设备端配置时（`caps.cfg`），菜单下面多一条分隔线和三行：
    **保存到板子**、**从板子载入**、**删除板子配置**。旧固件没有这三行，
    界面也就发不出它答不上来的命令。
  - 这三行还要过 `caps.cfg.writable` 这一关，它是板子在握手时自己报的：卷对代码只读
    （板上的 `boot.py` 不带 `storage.remount(...)`，或拷了没硬复位）时**保存到板子**和
    **删除板子配置**是灰的，**从板子载入**照常能点，菜单底部那行小字也换成
    "板子的卷对代码只读，保存与删除都用不了：把本仓库的 boot.py 拷到 G: 再按 RESET"。
    这个开关界面这边改不了，代码里也没有 `remount()` 的退路（`code.py` 调它会直接
    `RuntimeError: Cannot remount path when visible via USB`），只有改 `boot.py` 一条路。
    不带这个字段的旧固件按"能用"处理，点了才知道。
  - 这三行只管板子那一份，**板子里那份只在手动保存时改写**：载入不会覆盖板子，
    清空配置也不碰板子。想在两块板之间搬配置，就"保存到板子"→换板→"从板子载入"。
  - 删除板子配置也先弹确认框，问的是"删除板子上的配置？浏览器里那份不受影响"。
  - 菜单底部那行小字就是重点：**配置自动存在浏览器里**。
- 想绕过菜单直接清，也可以在浏览器控制台里执行 `localStorage.clear()` 再刷新。

板子上存着 `/config.json` 时，**连接**那一刻按这份规则走：

| 眼前的工作台 | 板子上那份 | 界面做什么 |
| --- | --- | --- |
| 什么都没有 | 有 | 直接载入，控制台打 `已从板子载入 {n} 项配置`，不问 |
| 有绑定 | 与这里完全相同 | 什么都不做 |
| 有绑定 | 不同 | 弹确认框。确定=载入板子那份；取消=留下浏览器这份，并打 `保留浏览器这份配置，板子上那份未改动` |
| 有绑定 | 没有文件 | 什么都不做 |

确认框只在**点"连接设备"**时出现：链路已经建立时板子重启（按 RESET、或从资源管理器保存
`code.py`）不会再问一遍你刚答过的问题。

> 想确认板子里到底存了什么，用**从板子载入**去问板子，别开资源管理器看 `G:\config.json`。
> Windows 显示的是卷的缓存，板子写进去的东西要等卷重新读一次（按 RESET 或拔插）才会出现在
> 那里——实测覆盖两份、等 20 秒，看到的仍是最早那份；板子删掉了的文件也会继续显示。
> 界面这条路径每次都直接问板子，说的是真话。反过来，如果你要在 G: 上拖文件部署固件，
> 先复位一次再拖，免得两边对"哪些扇区空着"的判断打架。

导入的配置不一定适合眼前这块板：**连接状态下的握手会拿设备报上来的能力表核对一遍绑定**，
把这块固件带不动的脚解除掉，并按功能在控制台点名，例如
`本固件不支持这些 PWM 脚，已解除绑定: GP1 GP2`、`这些引脚不符合本固件的 UART 配对规则，已解除绑定: GP10`。
被点名的脚回到引脚池，卡片还在，你换个合法的脚补上就行。离线导入不做这个核对，
连上板子时同样会补一次。从板子载入走的是同一条路，所以搬错板子也只会被点名，不会被写坏。

注意：配置的**默认**去处是浏览器。板子那一份要手动保存才有，而且它是板子卷上的一个文件——
不会被上电自动执行，只是"这块板子该这么配"的备忘。
板子断电重启后引脚配置是清零的，靠页面这边每秒的对账轮询补发回去。

## 8. 硬件注意事项汇总

这些是踩过的坑，写在这里省你的时间。

| 事项 | 说明 |
| --- | --- |
| 哪些脚进池子 | = 封装的 GPIO 数（RP2350A 30 个 / RP2350B 48 个，`platform_defs.h`）∩ 板级 `pins.c` 声明的脚。号码从声明名解析：`GPn` 直接读，只有 ADC 别名的（如 `A3`）按 `ADC_BASE + 通道号` 算出来，所以 Pico 2 的 GP29 在池子里。池子可能有洞（Pico 2 W 不声明 GP23/24/25），固件和界面都按 `caps.gp` 走，不写死脚数 |
| PWM 同 slice 共频 | 同一 slice 两个脚改频率会互相覆盖，需要独立频率就换脚，**或把其中一路切到 PIO**（每路独占状态机，不看 slice 分组）。slice = `(n//2) mod 8`（n≤31）/ `8+((n-32) mod 8)//2`（n≥32），偶 A 奇 B；**GP16 起会绕回 slice 0**，"不相邻"不等于"不同 slice" |
| PWM 频率下限 | `hw` 只接受整数 Hz，实测最低 9 Hz（1..8 Hz 都跑 9），低于 1 Hz 板子直接报错；1..8 由固件回报真实频率，界面把频率框标琥珀并写日志。要低频就切 PIO：窗口 0.0174553–15,000,000 Hz，实测 0.1 Hz 稳跑，代价是每路占一个状态机（全片 12 个） |
| ADC 脚位由封装定 | QFN-60 是 GP26..GP29（ADC0..3），QFN-80 是 GP40..GP47（ADC0..7）；Pico 2 的 GP29 被 IP 占用作 VSYS/3 监测——它以 `A3` 的身份在池子里，读上来的就是板供电除以 3 |
| I2C 必须有上拉 | 空闲时两线不拉高就报 `No pull up found`，这是接线问题不是软件问题 |
| I2C 引脚对固定 | SCL 奇、SDA 偶、`SDA ≡ SCL-1 (mod 4)`（不要求相邻），硬件两路实例，看角标 S/D 即可 |
| UART GP0/GP1 | 早先单口形态实测被 CircuitPython 控制台占用（`GP1 in use`）；0.1.14 双口固件实测可用，能力表已把它们算进 UART0 |
| UART 引脚规则 | 偶数脚可 TX、奇数脚可 RX，路号 = `((n+4)//8) mod 2`，全双工时两脚必须同一路 |
| SPI 数据脚分组 | SCK/MOSI/MISO 必须来自同一组（见 4.8 的表，gpio.h F1 完整转录），跨组建不起来；两组=两路总线 |
| SPI 时钟取整 | 时钟只能 150 MHz 除以偶数，上限 75 MHz。实测请求 2 MHz 实跑 1973684 Hz、10 MHz 实跑 9375000 Hz，界面在事务结果里写"实际 {0} Hz" |
| SPI 片选是普通 IO | CS 由固件当输出脚驱动，不占硬件 SPI 资源，但会占一个 GP |
| 复制 code.py 会重启板子 | 浏览器串口连接会断，需要手动重连 |
| 改 boot.py 要硬复位 | 按 RESET 或拔插 USB；Ctrl-D 软重启不会重跑 boot.py，端口还是一个 |
| 两个 COM 口分不清 | 共用同一 VID/PID，页面靠 nonce ping 认口；手工排查时发一条 `{"cmd":"ping"}` 看谁回 |
| 换板子 | PWM/ADC/I2C/UART 的能力表是开机探测出来的，SPI 是文档表投影到 `caps.gp`，界面自动适配，不用改代码 |

---

## 9. 连不上怎么办

按顺序检查：

1. **板子上电了吗** — CIRCUITPY 卷在不在？不在就重烧 UF2。
2. **code.py 在根目录吗** — 文件名必须是 `code.py`，不能放在子目录里。
3. **boot.py 在吗、硬复位过吗** — 只有一个 CDC 口说明双口没打开；
   按一次 RESET 再看设备管理器是否变成两个 COM 口。
4. **装 asyncio 了吗** — 打开**控制台口**看板子输出，`ImportError: no module named 'asyncio'`
   就是缺库，回 2.2 节。
5. **浏览器对吗** — 必须桌面版 Chrome 或 Edge，Firefox 和 Safari 不支持 Web Serial。
6. **两个口都授权了吗** — 选择框里同名的条目要全选，否则日志口/REPL 接不上，
   页面只能靠"踢一脚"重启设备。
7. **串口被占了吗** — 如果 Thonny、mpremote 或别的串口工具开着这两个 COM 口，先关掉。
8. **弹不出选择框** — 点的是"连接设备"吗？地址栏右侧有没有被拦截的权限提示？
9. **提示"找不到协议口"** — 板上的程序没在跑，也不应答 kick。用控制台口进 REPL，
   手敲 `import code` 看真实报错。

还不行，翻到 [03 使用示例](../03_Sample_Program_User_Guide/README.md) 的报错对照表，
或者直接开串口工具看板子吐了什么。
