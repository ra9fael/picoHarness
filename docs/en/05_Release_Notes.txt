PicoHarness Release Notes

The firmware version is written in the VERSION constant of code.py; the host version is the
repository commit. UI and firmware must be used as a matched pair: an old firmware does not
recognise new commands and answers "unknown cmd".


[20261013 0.1.17-gp29]

GP29 on the Pico 2 joined the pool. It is never spelled "GP29" — the board table declares it only
as A3 / VOLTAGE_MONITOR, and a CircuitPython Pin object exposes no number, so the old filter
("the name must contain GPn") treated it as nonexistent. The firmware now walks every Pin object on
board, deduplicates by identity, and reads the number off the declared name where one carries a GP
token; a pin whose only names are ADC aliases is numbered ADC_BASE + channel, ADC_BASE being the pin
behind A0 — declared as board.GP26_A0 here, so A3 = 29. Nothing about that is hardcoded per board:
the whole rule is computed from the device.

Measured on the board, GP29 does everything, and the capability tables widened with it: caps.adc
gained 29, and reading it gives VSYS/3 (raw 31815 -> 1.600 V -> VSYS ~ 4.80 V); caps.pwm is now 30
pins; caps.uart.rx gained 29; caps.i2c_pairs gained the eight pairs with SCL=29, and 29/28 measured
as "no pull up found", which is the sign of a routable pair. Over the protocol each path was walked
once: adc.cfg, pwm.cfg (reporting hfreq 990), gpio.cfg with it as an output, and uart.cfg
tx=28 rx=29 were all accepted.

Two UART measurements also got pinned down: UART(TX=GP28, RX=GP27) raises Invalid pins, which is not
the parity rule failing but the instance rule — 28 sits on UART0 and 27 on UART1, so they cannot form
one full-duplex pair; on their own, 28 works as a TX and 27 as an RX, and each built a bus. The live
half of tools/caps_audit.py now reconciles these tables against the documentation on hardware and is
green; against firmware that has no gp field it says "deploy the new firmware first" instead of
comparing against a fabricated contiguous range.

UI and docs followed: the pool grows GP29 on its own from caps.gp, and 01/02/04 restate the
addressable set as "the pins the board declares, numbered out of the declared name, with an
alias-only ADC pin numbered ADC_BASE + channel" instead of "the pins named GPn", quoting the
measurements above.


[20261012 0.1.16-spi]

SPI buses arrived. The firmware gained spi.cfg / spi.release / spi.xfer, read_state gained cfg_spi
and the spi list, and ready.caps gained the spi object (groups / max_buses / max_cs / baud_ceiling).

Pin legality was measured on the board with tools/spi_probe.py and then cross-checked against the F1
column of pico-sdk hardware/gpio.h — the two agree row for row. The sweep tried every ordered
(SCK, partner) combination:
53 were accepted and they fall into exactly two groups, 1571 pairs raised Invalid pins, and the 100
accepted triples are the cross-product of those groups. The conclusion is stored as the static
SPI_GROUPS table with no boot-time sweep, because the exhaustive version is 1600+ constructor calls
and the answer is a property of the silicon, not of the wiring.

The port's behaviour shaped the API: the constructor takes pins positionally (baudrate= raises
TypeError, half_duplex= raises NotImplementedError), a bare SCK is refused with Must provide MISO or
MOSI pin, so speed and mode are applied with configure() under the lock after the object exists.
A half bus (no MOSI or no MISO) is legal, matching UART. Chip select is not part of busio.SPI on this
port: the firmware drives each CS as a plain output that idles high and falls for one transaction, so
one bus can serve up to SPI_MAX_CS=4 devices. CS is registered under owner="spi" too, which makes it
show as occupied in the UI and stops a host from moving a select with gpio.set mid-transaction.

The clock keeps the honesty PWM introduced with hfreq, under the field name hbaud: the rp2 divides
150 MHz by an even integer only, ceiling 75 MHz, so a request for 2 MHz runs at 1973684 Hz and 10 MHz
at 9375000 Hz — the card prints that line in its result. This port's only full-duplex call is
write_readinto(), which wants two equal buffers, so the firmware pads a short write with 0xFF up to
max(len(w), r) and returns the first r bytes.

The UI gained the SPI lane (a bus card with SCK/MOSI/MISO slots plus CS0..CS3) and a transaction bench
that runs one raw byte transaction at a time. Hold CS segments a transaction in two, and choosing "—"
in the chip-select dropdown runs the clocks without asserting anything. Cross-group pins cannot be
dropped, and a third bus is refused in the UI. The configuration persists with the other buses, and
drift reconciliation folds CS order, baud and mode into the signature.

In the same build (no version bump) "which pins does this board have" was rebuilt against the official
documentation. The addressable set is package GPIO count ∩ the names CircuitPython's board definition
exports; the firmware reads it off board at boot and reports it as the new ready field gp (a Pico 2 W
has holes: no GP23/24/25, and GP29 only as A3/VOLTAGE_MONITOR). The meaning of caps.pins changed to
match: highest named pin number + 1, no longer a pin count. SPI_GROUPS is the complete 48-row F1
column of gpio.h, projected onto gp before it is sent, so the UI, the mock and the firmware all read the
same set and the hardcoded pin counts are gone. Host-side masks now set and test bits with 2**n
because JS 1<<n wraps at n>=32; a 48-bit mask is still inside the exact-integer range.
tools/caps_audit.py is new: --static lays the documented rules over all 48 pin numbers and parses
SPI_GROUPS and the UART instance formula out of code.py, and with a board attached it audits the live
caps. Both manuals now quote the exact conditions from gpio.h / platform_defs.h / the CP common-hal
sources instead of paraphrasing: I2C is the hardware DW_apb_i2C rather than PIO (an earlier entry in this
file called it PIO — that line was wrong) and a pair need not be
adjacent, UART is even-TX/odd-RX with instance ((n+4)//8)%NUM_UARTS, and PWM wraps back to slice 0 at
GP16 ("not adjacent" is not the same as "not the same slice").


[20261012 0.1.15-pwmhz]

The firmware now tells the truth about PWM frequency. The rp2 divider can only generate
125 MHz/(div×(top+1)), so the measured floor is 9 Hz: requests of 1..8 Hz all run at 9, and higher
requests quantize (1000→990, 2000→2035). read_state's pwm entries gained hfreq (what the slice
actually runs at) alongside freq (what you asked for). The UI paints the frequency field amber with a
tooltip, and writes a log line when the gap exceeds 5%. Below 1 Hz the firmware still refuses, since
PWMOut takes whole hertz.

Also fixed a blinding side effect: when pwm.cfg failed to build the object (a second pin of a busy
slice answers RuntimeError: Conflicting settings for shared resource) the pin stayed claimed as "pwm"
with no object behind it, so read_state raised TypeError and every later gpio.state was unusable. The
failure path now gives the pin's ownership back.

UI fix: clicking a pin and then a lane used to work only on the I2C/UART card slots. The four per-pin
lanes wired dragover/drop alone, so clicking a lane that was glowing for the selection did nothing —
while the selection hint literally says "click a highlighted lane to bind". Click and drop now share
one assign path, and clicking the pin pool un-binds the selected pin too. The duplicated prefix in
hints ("GPGP4") is gone: pinLabel already carries GP, and the strings hardcoded another one.


[20261012 0.1.14-uart01]

probe_uart no longer drops GP0/GP1 from the candidate list. In the single-port era that UART0
TX/RX pair was held by the CircuitPython console (busio.UART measured "GP1 in use"); on this
dual-CDC firmware the same check passes — uart.cfg with tx=0/rx=1, tx=0 alone, and rx=1 alone all
built, and after release gpio.state listed no uart bus with cfg_uart=0. GP0/GP1 are back in
caps.uart's tx/rx/pairs.

No UI change: the capability table comes from the device, so one reconnect lights up the T / R
badges on GP0/GP1. Documentation followed — manual UART notes and hardware table, protocol guide
section 2.1, and the sample guide's GP0/GP1 paragraph now say they are usable.


[20261012 0.1.13-dualcdc]

The firmware moved to a dual CDC topology: boot.py calls usb_cdc.enable(console=True, data=True),
so the JSON-lines protocol and the binary frames run on the data port while the console port goes
back to CircuitPython itself (boot banner, print, tracebacks, REPL).

Added the hello command: it answers with the same payload as the boot-time ready broadcast. Caps
are probed once at boot and cached (the I2C sweep is slow), so a host that joins later no longer
has to restart the device to learn the version and capability table.

The host now identifies the protocol port with a nonce ping: both CDC ports share one VID/PID and
getInfo() cannot tell them apart, so the only port that answers is the one running code.py. All
authorized ports are pinged in parallel, connection starts on the first positive answer instead of
waiting the silent ones out, and role verdicts are cached for 4 s — a reconnect costs zero clicks and
no longer pays another round of timeouts. Only when nothing answers does the host restart the device
program, and it picks that candidate by which port actually carried device traffic, because
usb_cdc.data ignores Ctrl+C/Ctrl+D and kicking it cannot wake code.py.

The console gained an "attach log port" button: on a dual-CDC board the page attaches the console port
by itself right after the handshake, so device print output and tracebacks are mirrored live, and the
button is still there when the port was never authorized. The status light now names the port roles —
"Connected · dual CDC · log port ✓", a single-port board reads "Connected · single port (legacy)" and
keeps a standing warning banner at the top of the page. Entering the REPL touches only the console
port, so the data port's connection is never dropped and leaving the REPL costs no port picker; to be
frank about it, though, the REPL is entered with Ctrl+C, which stops code.py, so during that time
nothing answers the protocol — dual CDC removes the re-picking, not the interruption.

The console also gained a "raw stream" switch, off by default: with it on, the protocol port's raw
JSON/binary bytes are mirrored into the terminal too, for when you want to read the wire format.

The header gained a "Config" menu: export the configuration as picoharness-config-<timestamp>.json,
import a file and apply it immediately, or clear everything behind a confirmation. While connected, the
handshake checks every restored binding against the device's own capability table and un-binds pins
this firmware cannot drive, naming them in the console — so a config copied from another board no
longer sits there looking alive while every request fails.

Failure messages now read symptom → cause → next step, e.g. "No protocol port found" states the two
likely causes (code.py missing, boot.py changed without a hard reset) and the action for each.

A single-port fallback is kept for one release: without boot.py on G:, usb_cdc.data is None and the
firmware stays on one port; when hello fails, the host falls back to restarting the device and
waiting for its broadcast ready line. The next release drops single-port mode.

Two constraints measured on hardware: boot.py only takes effect on a hard reset (a Ctrl-D soft
reboot does not re-run it), and the CircuitPython REPL wants \r\n — a line ending in \n alone is
echoed but never executed.

Firmware and UI were committed separately (feat(fw), feat(ui)).


[20261011 0.1.11-uart]

UART bus lanes landed: TX/RX slots, baud rate, and a write/read transaction desk.

Added a live UART terminal tab in the console, one per bus; keystrokes send bytes directly, with
a HEX/text rendering toggle. The clear/copy/export buttons follow the currently visible tab.

UART RX moved to an event stream (subscribe to the topic uart.<id>); empty reads no longer block
the scheduler.

Fix: busio.UART's default 1000 ms read timeout could freeze the whole cooperative event loop.
Buses are now created with timeout=0 explicitly, manual reads use a 200 ms bounded wait and are
restored to non-blocking afterwards.

Fix: GP0/GP1 are occupied by the CircuitPython serial console; the probe table now excludes them
from caps.uart, so the UI cannot offer a pin pair that is guaranteed to fail.

Fix: every new handshake clears the live/rejected latches of the bus cards. Previously, after a
firmware reflash the device lost its volatile configuration while stale latches made the UI skip
that bus forever and never resend its configuration.

I2C and UART lanes were committed separately (feat(i2c), feat(uart)).


[20261010 0.1.7-i2c]

I2C raw bus transaction lanes: i2c.cfg / i2c.scan / i2c.xfer / i2c.release, supporting
write-only, read-only and repeated-start write-then-read transactions.

The firmware now exhausts the legal SCL/SDA ordered pairs at startup and exposes them as
caps.i2c_pairs; the UI highlights droppable slots by role and rejects illegal drags outright.

The rp2 PIO I2C legality rule is confirmed: SCL takes an odd GP, SDA an even GP, and
SDA ≡ SCL−1 (mod 4) must hold. "No pull up found" is a wiring issue, unrelated to pin selection.

Multi-pin buses were integrated by adding an optional renderLane hook to FunctionDef; a bus lane
renders its own card. Configuration persistence gained buses[].


[20261010 0.1.6-temp-sub]

Added the internal temperature virtual channel (wire pin number 100). This build does not expose
board.TEMPERATURE_SENSOR, so microcontroller.cpu.temperature is inverted into a 16-bit equivalent
raw value, which lets temperature reuse the existing u16 telemetry pipeline completely.

Added MQTT-style event subscription sub/unsub (with retained snapshots). Topic gpio.in is
strictly gated; adc.<pin> only tunes the per-channel deadband (ADC has no polling fallback, so it
is not gated).

Rewrote the scope panel: channel colors are assigned stably per pin; wheel zoom anchors on the
sample under the cursor; drag to pan; crosshair with a readout box; Roll / FIFO capture modes
with optional depth; binary frames gained a kind registry, so adding a telemetry stream only
requires registering its parser.


[20261010 0.1.5-binstream]

adc.stream supports fmt=bin, transmitted as struct frames (0xAA 'W' + u16le length + payload)
written to usb_cdc in a single atomic write. JSON now uses compact separators, saving about 15%
for the same content.

The host switched to byte-level demultiplexing of the mixed stream, separating ASCII lines from
binary frames on the same serial stream.

ADC chip readouts gained EMA smoothing and a 250 ms timed refresh; the scope gained axis units
and k·x+b correction.


[20261010 0.1.4-adcstream]

Added adc.stream / adc_streamer batched waveform frames; deadband events are muted while the
stream is running. Added the scope panel (collapsible, 4 channels, 2048-point ring buffer, rAF
repaint, selection and collapse state persisted).

Fix: UI stutter under three concurrent channels. Measurements show the firmware and protocol
layer are not slow (0-channel RTT median 11 ms, 3-channel 19 ms, zero timeouts); the root cause
was per-event rendering, eliminated by batch frames plus a single repaint per frame.


[20261010 0.1.3-stdinpoll]

Fix: sys.stdin.read(1) blocks until a byte arrives, so command_reader froze the entire event loop
at its first step and no sibling monitor ever got a step. stdin is now gated with select.poll(),
and tasks are gathered by task handle per the official guide.

Fix: under mpy, gather awaiting bare coroutines in order misbehaved; gather accepts Task objects
only.

Rebuilt the PWM frequency editor as a "numeric preset × unit preset" combination, with
float-safe persistence.

Known device-side limits: on rp2, changing .frequency of a fixed-frequency PWMOut raises
Invalid variable_frequency, so the firmware rebuilds the object when the frequency changes;
frequency accepts integer Hz only, floor about 7.4 Hz. On USB CDC, print(flush=True) raises
OSError [Errno 22] on every call (the text still goes out), so no flush is used.


[20261010 0.1.0-adc / 0.1.1-montdbg]

Added the ADC readout lane: adc.cfg / adc.stop, 100 ms sampling, change push at an about 0.5%
deadband. Display favours voltage with a switch to raw values; the format choice persists with
the configuration.

Added the dbg event, reporting each monitor task's liveness and exceptions (before this, gather
swallowed dead tasks and failures looked like silence). The pin model extended to 29 pins; the
ADC display cycles between V/mV/raw.


[20261009 0.0.9-nbstdin]

Command reading made non-blocking, fixing "an answer only appeared at the next request".

The UI gained console copy/export and a PWM frequency preset dropdown; the workbench
configuration is stored in the browser's localStorage, silently restored after connect and
self-healed through drift reconciliation.


[20261009 0.0.8-async]

The firmware moved to an asyncio main loop; gpio_in edge events push at 50 ms (CircuitPython does
not ship asyncio, so run circup install asyncio).

The host switched input levels to event-driven, with polling reduced to a 1 s reconciliation
self-heal pass.


[20261009 0.0.7-arbiter]

The firmware gained a command dispatch table and pin ownership arbitration by an owner arbiter
(claim/release, PWM preemption may force).

The host was refactored in layers: transport / rpc / model / workbench. Functions register as
FunctionDef entries, so adding a bus function only takes writing a def and registering it.


[20261009 0.0.6-wb]

IO assignment workbench (pin pool plus function lanes, bind by drag or click, an occupied pin
automatically bumps the previous one). The debug console integrated xterm.js, bilingual
Chinese/English.

History before this is out of scope for this document: the project used PicoJig as its blueprint
and became a single-file host app built on CircuitPython plus browser Web Serial straight over
USB CDC.
